# Agent Note: Shadow 人设仅在部署挂载记忆工具时教其使用

Status: implemented

[English](2026-09-14-shadow-memory-guidance.md) | 中文

## 问题

设计把记忆三件套（`memory_search`、`memory_read`、`memory_append`）作为显式启用的用户 memory 访问放进 Shadow 的模型面，对话宿主的 allowlist 布线也已经探测并放行部署实际挂载的工具——但从未有任何东西教模型何时使用它们。工具描述携带了信任标签策略，然而 Shadow 的人设对记忆只字未提，模型没有任何行为指引去在人类引用先前上下文时搜索、或在人类要求保留时追加。部署的 vault 从首次启动起就一直是空的：工具可达，却没有任何模型有理由调用它们。

## 决定

对话宿主再注册一个作用域提示词段落——`experimental:shadow-memory`，order 11，与人设并列——仅当 `enabledMemoryTools` 返回完整三件套时注册。段落的规则镜像设计的使用策略：人类引用先前上下文时先搜索一次、并在宣称没有记录之前先搜；只追加人类要求保留的内容，以人类为来源，绝不把影子自己的推断提升为已确认的偏好；每次记忆失败逐字上报并继续，因为记忆是可选上下文。注册以完整三件套为条件，是因为文本点名全部三个工具：部分挂载得到的是沉默而不是对不存在工具的承诺；没装 project-memory 的部署保持人设与提示词形状完全不变。

## 备选方案

**把记忆规则无条件折进人设文本。** 拒绝：人设是静态的，而记忆面随部署变化——没装 project-memory 的部署会携带描述不存在工具的指令，其他所有部署也要为自己并不具备的面支付指导 token。

**让 project-memory 自己贡献指导段落。** 拒绝：包级段落会到达每个继承全局提示词的代理作用域，而设计把用户 memory 访问范围限定在 Shadow 的面上；指导属于 allowlist 组合的那个作用域，那里的探测已经知道真相。

**等控制器侧记忆行为（任务开始召回、验收后追加最终总结）一起发布。** 推迟而非拒绝：控制器行为属于 presets 与派发流程，改变每个控制器会话的 token，需要单独决策；Shadow 指导独立成立，今天就解除人类常驻对话的阻塞。控制器侧随后已以[全局使用策略段落](2026-09-14-project-memory-usage-policy.zh.md)落地，本作用域对其按名遮蔽。

## 结果

买到的：挂载 project-memory 的部署得到一个会在先前上下文引用时搜索、并记录人类要求保留内容的 Shadow；没挂载的部署毫无变化。指导、三个记忆 schema 与人设共享同一请求前缀，挂载状态不变时 KV-cache 复用不受影响。

代价：挂载记忆时指定会话的提示词增加该段落；指导是引导而非强制——信任标签规则仍活在工具描述与宿主的筛查里，忽略该段的模型也得不到它本不能调用的任何东西。

## 测试

`shadow-agent.host.spec.ts` 通过组装后的模型请求钉住两面：挂载三件套时请求携带指导（"Memory holds durable facts only"）；未挂载时请求中既无指导也无任何工具名。
