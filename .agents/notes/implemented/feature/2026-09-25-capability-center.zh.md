# Agent Note：能力中心统一展示各自拥有的能力页面

Status: implemented

[English](2026-09-25-capability-center.md) | 中文

## 问题

侧栏仍名为“专家模式”，无法概括同级的“技能”“连接器”和记忆库。单独的记忆库入口也割裂了相关的本地能力。

## 决定

侧栏入口和其共享弹窗统一命名为“能力中心”，并提供“专家”“技能”“连接器”和“记忆库”四个选项卡。“专家”页保留已挂载专家目录。插件清单包向根级键控插槽 `capabilities.center.tab` 提供“技能”和“连接器”，并复用设置页使用的管理回调。项目记忆库 UI 包向同一插槽提供“记忆库”页，用于列出、搜索、预览已配置的 Vault，复制绝对路径，并向对话草稿添加文件引用。Vault 保持只读。能力中心只挂载当前选中的页面；所属包未挂载时会明确显示不可用状态。每个领域的服务与行为仍由各自的包拥有。

交付边界始终是插件包本身。能力中心不要求 Desktop 或 Host 主体补丁；profile 组合包声明已发布的数据包依赖，`expert-team` 从已安装的依赖闭包解析这些包名，不再使用 `process.cwd()`。UI 包保持公开发布，并用可选 peer 连接跨页面插槽类型，因此 DSH 更新后仍可通过公开的 Remote 与插槽契约挂载插件。

## 备选方案

**保留“专家模式”名称，只增加选项卡。** 否决：名称只描述四个同级入口中的一个。

**让记忆库继续使用独立的侧栏入口。** 否决：用户仍需要分别打开入口才能找到相关的本地能力。

**把全部能力实现移动到中心包。** 否决：这会复制宿主管理和 Vault 行为的既有拥有关系。

## 结果

用户通过一个常驻入口访问四个页面，各提供方继续使用已有的数据与变更路径。提供方缺失时会显示清晰的不可用状态，而不是编造内容。页面只在选中时挂载，因此离开标签后本地视图状态会重置；记忆库只在标签挂载后读取 Vault，且从不写入 Vault 文件。

## 测试

聚焦套件覆盖四标签外壳、插槽分发与后备状态、键盘导航、技能与连接器管理、记忆库加载、不可用状态、过期异步结果及文件引用。三个受影响包的套件共九个文件、66 项测试通过。
