# Agent Note: 专家中心操作通过新对话交接

Status: implemented

[English](2026-09-16-expert-center-summon.md) | 中文

## 问题

目录让用户可以发现已挂载专家，但用户无法直接从专家卡片进入使用该专家的对话。如果浏览器直接修改编排状态，也会越过宿主拥有的运行与批准边界。

## 决定

专家卡片提供悬停或焦点可见的“召唤”操作。详情面板提供“召唤专家”和三个由区域字典拥有的示例问题。每个操作都会关闭目录，暂存普通专家身份与可编辑提示，并调用已有的 `uiWorkspace.startSession()` 流程。`ExpertSelectionController` 等待生成空白会话，通过 `ctx.conversation.input` 写入提示，并在 `conversation.input.left` 发布会话级专家标签。用户通过普通输入框提交提示；浏览器不会直接调用 `expert_team_run` 或 `expert_team_approve`。

## 备选方案

**由浏览器直接调用 `expert_team_run`。** 否决：宿主/模型边界拥有编排、关口与运行历史，界面不应建立第二条变更路径。

**立即提交召唤提示。** 否决：选定专家和提示会保持可见、可编辑，用户可以补充上下文、修改措辞或在发送前移除选择。

**只在目录中显示选择状态。** 否决：选择必须在用户编辑并提交新对话的位置继续可见。

## 结果

参考图中的卡片与详情交互现在可以完整、可逆地进入已有 Conversation 界面。成功交接会生成带可见专家标签与草稿的空白会话；提交后沿用已有的面向模型的专家团队工具。没有可用 Workspace 时，选择会暂存，直到正常 Session 流程生成空白会话。

## 测试

专家中心测试覆盖卡片召唤、详情召唤与示例问题操作。选择测试覆盖提示暂存、异步空白会话协调与标签移除。DevFrame 浏览器实时流程确认生成了带预填提示与专家选择标签的新空白会话。
