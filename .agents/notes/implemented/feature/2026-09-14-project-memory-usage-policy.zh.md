# Agent Note: 记忆使用策略是全局条件段落，拥有自有记忆面的作用域按名遮蔽

Status: implemented

[English](2026-09-14-project-memory-usage-policy.md) | 中文

## 问题

有界记忆设计规定了使用行为却没有指定载体：任务开始时召回一次，验收后控制器的最终任务总结成为候选项目笔记。工具在每个作用域都存在，但没有任何东西教任何代理这个行为，于是部署的 vault 从首次启动起就空置。看起来显而易见的载体其实都不合适：`standard` preset 的人设是部署无关包里的静态文本，在那里教这些工具会对没有记忆的部署承诺不存在的工具；而在 shadow 路由器的控制器供给里做逐作用域组合手术，是为设计原话里本就属于模型在既有回合中的行为而新增供给机制。

## 决定

`project-memory` 自己承载策略。其插件仅在解析出的 spec 配置了 Vault 时——即设计的 "when enabled"——注册一个全局提示词段落（`project-memory:usage`，order 40）。文本从模型视角教授分角色的行为：任务开始先搜索一次，摘录不够时才读全文；任务上的工作被验收后，追加一条简短项目笔记、以自己为来源、观察绝不是已确认偏好；人类的偏好仅在其明确要求时进入 `user` 作用域；绝不复制会话记录、秘密、凭据或环境转储；每次记忆失败逐字上报并继续。

自行组合记忆面的消费者在各自作用域按名遮蔽该全局文本——作用域提示词服务本就拥有这一机制。Shadow 对话宿主无条件这样做（一个同名的空段落），因为其作用域携带自己的记忆段落（`experimental:shadow-memory`，用户作用域语义），一个作用域应该有一个记忆面，而不是两份。

## 备选方案

**改 `standard` preset 的人设。** 拒绝：该人设是 `agent-presets` 里的静态文本、与部署无关；没装 project-memory 的部署会携带描述不存在工具的指令，而 preset 编辑无法对任何东西做条件化。

**由 shadow 路由器的控制器供给注册作用域段落。** 本轮拒绝：路由器需要探测记忆工具并向每个供给的控制器作用域注册指导——为全局层本已分发的文本新增供给机制，而且设计允许阅读的 worker 将一无所获。

**宿主拥有的注入而非提示词指导**（把召回结果注入任务开局回合、由完成门追加总结）。推迟：设计禁止独立的反思会话，引导形态的行为不需要新的会话事件、回执或失败管路；若实践中引导被证明不足，完成门才是重新审视的诚实位置。

## 结果

买到的：配置了 Vault 的部署中，每个看到记忆工具的会话都被教授设计的使用行为——控制器任务开始召回、验收后记录总结；worker 召回；唯独 Shadow 保持自己的面。未配置的部署中提示词不含任何记忆内容，与诚实报告 `MEMORY_UNAVAILABLE` 的工具一致。

代价：配置部署中该段落的固定文本进入每次请求的提示词（一段有界文本，前缀稳定）；指导是引导而非强制——信任标签规则仍活在工具描述与宿主的筛查里；段落名 `project-memory:usage` 是跨包契约，Shadow 宿主以带交叉引用注释的字符串字面量遮蔽它，因为一个常量不值得在两个实验族之间开一条依赖边。

## 测试

`plugin.spec.ts` 通过组装后的提示词钉住：配置 Vault 时段落存在、未配置时缺席、随插件 fiber 释放而移除。`shadow-agent.host.spec.ts` 钉住 Shadow 的遮蔽：注册全局段落后，Shadow 组装的请求携带自己的记忆指导而不含全局策略文本。
