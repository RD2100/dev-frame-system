# Agent Note: DevFrame 总控侧边栏入口与 Session ID

Status: implemented

[English](2026-08-15-devframe-global-controller-sidebar-entry.md) | 中文

## 问题

DevFrame 总控会话已经持久化并有稳定地址，但普通 Web 界面需要一个明确入口来打开它并查看会话身份。空白的总控会话不能被误判成普通“新会话”占位符，用户也不应该为了复制 Session ID 去查存储文件或网络请求。

## 决策

桌面启动脚本使用普通 Web Profile，并叠加 `scripts/devframe-web.patch.yml`。这个薄叠加层只挂载已有的 DevFrame 总控服务和浏览器包，不挂载有界的无头任务命令，因此 Web 的 `--port` 等参数保持原有语义。

控制会话浏览器包在侧边栏底部提供唯一的 `总控` / `Global Controller` 入口。它从已加载的会话目录中找到 `devframe-global:<profile-id>` 并打开已有会话，不创建第二个会话，也不增加写路由。同一个底部入口带有三点菜单，提供 `复制 Session ID` / `Copy Session ID`；回调使用共享剪贴板工具，不改变会话或服务端状态。

Workspace 浏览器会从普通工作区和“未分组”会话行中排除 `devframe-global:`，因此底部入口是唯一的总控入口。持久化的 `controller/identity` 事件仍供 Host 与客户端投影使用，但不再作为聊天卡片显示；对话区域只承载实际对话。

## 考虑过的替代方案

**等总控产生消息后再显示**——这会让持久化的总控无法从产品界面进入。独立的底部入口既保持可达，又不会在普通会话中重复显示。

**把总控放进某个项目行**——总控不属于任何项目；这样嵌套会传达错误的作用域，也会让跨项目协调语义含混。

**在 Web 启动器里挂完整 DevFrame 任务包**——任务命令解析器会接管 `--port` 等 Web 参数，所以启动器只挂总控服务和浏览器行；完整任务包仍由无头 `devframe` Profile 提供。

**只在开发者检查器里显示 ID**——Session ID 是用户可见的身份合同，应放在稳定、容易发现的底部入口菜单里复制。

## 后果

DevFrame 启动后的第一屏现在只有一个持久化的底部总控入口。总控还没有产生模型消息时也能打开，普通项目和会话行继续保持 DSH 原生语义。多个 Profile 共用一个会话目录时仍可有不同总控 ID，前缀会明确它们的作用域。

## 测试

Workspace 与控制会话客户端测试覆盖普通树排除总控、底部入口的打开/禁用状态、生命周期释放、复制 ID 菜单回调和身份资料卡抑制。真实 Web 冒烟测试通过桌面启动脚本确认只有一个底部总控入口、普通列表无重复总控、聊天流无身份卡，并且 `复制 Session ID` 菜单可用。
