# Agent Note: 记忆笔记经由宿主规范化的标签锚定到实体

Status: implemented

[English](2026-09-14-memory-entity-anchoring.md) | 中文

## 问题

vault 的召回是纯正文子串匹配，因此对代理记忆最重要的查询——"这个项目的一切"、"关于这个主题我知道什么"——没有好答案：用不同名字指称同一主题的笔记（路径、简称、中文描述）永远匹配不上，双语语料进一步割裂。业界看到的完整解法（mem0 的图谱时代设计、Zep/Graphiti）是知识图谱，但其成本——每条笔记一次抽取 LLM 调用、图数据库、实体间关系边——恰恰是有界记忆设计在实测需求之前拒绝支付的。

## 决定

不要图基础设施的实体锚定。`memory_append` 接受可选的模型提议 `entities` 标签；宿主将其规范化（去空白、折叠空格、小写、至多 64 字符的单主题形态、每条至多 8 个、与正文同等的秘密筛查），并以一行 front matter 存储。项目作用域的笔记始终携带其工作区标签——这是宿主已知的唯一确定性实体。`memory_search` 增加可选的 `entity` 过滤参数，以同样方式规范化，"关于 X 的一切"就是对既有有界候选遍历的一次确定性查找；命中携带笔记的标签，模型可以顺藤摸瓜。supersession 链条仍是有效期窗口，使用策略段落与 Shadow 段落教授"同一主题复用同一标签"的纪律。

扁平语料仍是唯一事实源：不存在单独的索引文件，候选遍历就是索引；只有当语料增长到能测出需求时，标签才毕业为真正的实体节点（摘要、别名、关系边）。

## 备选方案

**先做 BM25 关键词打分。** 推迟：在本部署的双语语料上它需要中文分词或 bigram 索引才能工作，而且它回答的是相关性而非范围——"关于 X 的一切"依然没有答案。文本相关性以后再进来，作用在实体过滤后已经收窄的结果集上——仅当单实体下笔记数增长时。

**真正的实体图谱（Graphiti 式抽取、带演化摘要的实体节点、关系边）。** 推迟而非拒绝：每一块都是同一 schema 的规模驱动升级——标签变成节点 id，别名进入登记表，真正有人问关系查询时才出现边。这里没有任何东西堵死那条路。

**召回时用 LLM 抽取标签。** 拒绝：它在写入路径上放了一次 LLM 调用，去获取写作模型本已知道的结构；而且设计的公证处模型要求模型提议候选、宿主派生权威元数据——规范化做的正是这件事。

## 结果

买到的："关于 X 的一切"成为跨双语笔记的有界确定性查找；项目笔记以零模型成本自动锚定其工作区；标签 ride 既有筛查，标签走私不了正文走私不了的东西。代价：追加工具 schema 多一个可选参数，命中多一个可选字段，标签纪律（同一主题复用同一标签）是引导而非强制——本版本没有别名合并登记表，别名问题只解决到写作模型保持一致的程度。

## 测试

`append.spec.ts` 钉住规范化往返（去空白/小写/去重加自动工作区标签）、带命中标签的实体过滤搜索，以及对携带秘密、形态非法、超限标签的响亮拒绝。插件与 Shadow 提示词文本教授打标签纪律。
