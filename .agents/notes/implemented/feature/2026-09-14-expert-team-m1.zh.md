# Agent Note: 专家团队经人工关口的阶段子代理运行角色数据包

Status: implemented

[English](2026-09-14-expert-team-m1.md) | 中文

## 问题

harness 缺少运行多专家流水线的途径：一项研究任务需要几个不同人设（视角发现、文献综述、选题、方法设计）按依赖顺序执行，产物在阶段间传递，并在关键节点由人类把关质量。自然的接缝——agent loop——恰恰是不允许新增行为的地方，而现有的子代理机制（agent-hierarchy 派发）解决的是另一个问题：工作树上的角色绑定 worker，而不是带人工关口的角色化手艺会话。没有这个归属，每次部署都要为任务临时拼装提示词、产物交接与评审纪律。

## 决策

expert-team 插件把角色数据包作为数据挂载，在既有 agent 机制之上编排流水线阶段，不改循环。数据包（`team.yml` 加 `experts/<id>.md` 加技能加结果 schema）在加载时响亮失败校验——阶段 id 唯一、`depends_on` 只向后、专家/schema/技能文件存在——每个违规都携带稳定的 `EXPERT_TEAM_*` 代码。每个阶段经代理注册表的 scoped-create 面派生子代理（`ctx.agents.create`，其 `setup` 组合角色、包技能，以及同时作为可见性限制与执行器守卫的工具允许清单），再以 `followup()` 加 `whenIdle()` 驱动一轮。

阶段专家以回复正文作为产物，并在最末尾给出围栏 JSON 结果对象；默认没有写文件工具，但数据包可以明确授予 `write`／`edit`，在运行目录内执行代码变更。运行时仍是声明产物契约的唯一写入者——按声明的产物名和包的 JSON Schema 校验结果，契约通过后才原子写入正文，失败时对同一会话至多重驱两次，让修订留在上下文中。带关口的阶段让运行停车（`waiting-approval`）；批准让流水线推进，驳回把产物连同评审者批注退回同一阶段会话作为修订指引，耗尽重试的阶段以失败状态停在它的关口，批准被拒绝（不存在可下传的已接受产物）。`approved` 决定还向被关口阶段的会话尽力投递一次批准后后续消息（followup），让人设的验收后记忆笔记获得真实一轮；后续消息即发即忘，失败按名记录，推进不等待它。运行状态以内存为权威，并在每个提交点镜像到 `<artifactsDir>/<runId>/run-state.json`；运行不跨进程恢复。把产物记入 project-memory 委托给数据包的工具允许清单——声明 `memory_append` 的专家可以按[实体锚定设计](2026-09-14-memory-entity-anchoring.zh.md)以研究主题为标签记录笔记——编排器自身从不调用记忆。

## 备选方案

**把阶段映射到 agent-hierarchy 派发。** M3 层级模式已取代原先的延期决定：保留 scoped-create，因为专家阶段不需要工作树，并通过可选的 session-identity 注册表记录 controller／lead／worker 绑定，而不调用 `agent_dispatch`。当前角色绑定决定见 [M3 记录](2026-09-15-expert-team-m3.zh.md)。

**给阶段专家写文件工具，让它们自己持久化产物。** 否决：产物边界将取决于每个包作者的工具纪律，写了一半的文件可能下传，schema 校验会落在持久化之后而不是之前。回复正文协议让运行时保持唯一写入者，并把 schema 关口纳入验收。

**用数据库保存运行记录以支持跨进程恢复。** 延期：M1 的消费者读取镜像的 `run-state.json`，尚无部署跨重启运行团队；恢复成为真实需求时再加存储接缝。内存记录加文件镜像让每次运行只有一个生命周期拥有者。

**核心自有的按产物记忆写入。** 延期：核心需要自己的 project-memory 依赖和它并不具备的实体标签来源；包允许清单机制已经给专家诚实、经筛查的记忆访问，未配置记忆时如实报告 `MEMORY_UNAVAILABLE` 而不使阶段失败。

## 后果

买到：部署以一行配置加一个数据目录挂载专家团队；人设、handoff 核查清单与机器可查的结果契约都住在版本化的包文件里；执行器强制关口的停靠与批准记录（带关口的阶段停车、`expert_team_approve` 记录决定），而决定来源——说话的确实是人类——由用法小节以提示词钉住；产物是 `<artifactsDir>/<runId>/` 下的文件，绝不作为内容回到提示词。成本：运行串行且随进程消亡（无恢复），未挂载 session identity 时层级角色绑定是 best-effort，围栏 JSON 结果协议要求模型保持严格的回复形状（有界重试吸收失手），专家质量只是引导——关口检查声明契约，不检查手艺。

## 测试

目录单元测试钉住挂载、每种响亮失败的挂载错误与查找；解析器测试钉住 expert-md 与 team.yml 契约；结果协议测试钉住回复拆分、契约检查、schema 逐条枚举与简报组合。编排测试用脚本化 mock 适配器驱动真实插件挂载：阶段按序、契约重试、关口停车、驳回后同上下文修订、批准恢复、咨询隔离，以及经工具面的每个稳定失败码。REAL 组合测试经真实 Loader 启动 cordis.yml，同时挂载 fixture 包与 shipped 论文、开发数据包，从产品面证明包格式；同一次挂载校验论文数据包十阶段链与开发数据包六阶段层级链。录制会话的快照层推迟：录制场景需要 provider key，目前没有录制任何场景；REAL 组合规格以 mock 模型适配器驱动同样四个工具，承担过渡期的模型可见覆盖。
