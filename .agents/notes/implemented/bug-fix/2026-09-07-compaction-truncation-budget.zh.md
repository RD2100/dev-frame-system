# Agent Note: 限制自动摘要截断失败

Status: implemented

[English](2026-09-07-compaction-truncation-budget.md) | 中文

## Problem

达到 token 上限的摘要不会缓解对话压力。在每个模型步骤前重试会反复消耗生成时间，却无法提交检查点；普通对话推进不会修复摘要输出上限。

## Decision

`compaction-basic` 通过 `maxAutomaticSummaryFailures` 限制每个活动 Session 和实际摘要策略的连续自动 `MAX_TOKENS` 失败，默认一次。预算耗尽后跨步骤和轮次暂停自动摘要，同时保留无模型修剪。摘要成功提交，或摘要提供方、模型、输出上限、失败预算变化后恢复执行。手动尝试仍可使用；失败或无内容可压缩的尝试不会恢复执行。取消不消耗此预算，溢出恢复仍要求持久化上下文取得进展后才重试原始请求。

## Alternatives considered

**减少 `compactionRetries`。** 该字段限制成功缩减后仍超过阈值的次数，不能限制跨步骤的失败摘要。

**在普通响应或每轮之后重置。** 两者都无法证明摘要器能够完成，因此都会重新产生反复成本。按时间冷却同样会在没有恢复证据时重试未变化的失败策略。

**接受截断的检查点。** 不完整检查点可能遗漏待办任务和约束。现有失败关闭的摘要事务仍然具有决定权。

## Consequences

预算保存在进程内，因此重建后端会获得新的预算。预算耗尽时仅产生一次带路由和恢复说明的警告，不增加模型输入或会话事件类型。真实循环测试覆盖截断次数上限、跨轮保留、独立会话、实际路由恢复、手动成功、取消以及溢出错误保留。手工编写的 `compaction-truncation-budget` 无密钥场景通过明确的回放覆盖输入提供失败的辅助流，然后比较真实 headless profile 的持久化日志：一个失败的压缩标记对、两个工具结果、三个完成的模型步骤、没有摘要检查点，以及已完成的轮次。跨轮保留由真实循环测试覆盖。前缀缓存复用和检查点语言仍由现有笔记负责。
