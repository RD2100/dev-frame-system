# Agent Note: 对实际工作树内容生成指纹

Status: implemented

[English](2026-09-07-fingerprint-actual-worktree-content.md) | 中文

## 问题

HEAD 和索引记录描述已提交及已暂存内容，并不描述检查或工具会读取的未暂存修改或未跟踪文件。仅使用这些记录会让完成准入在审查后源码发生变化时仍然放行，因为两项 Git 观察都没有改变。

## 决策

[源码指纹](../../../../packages/experimental/devframe/src/source-fingerprint.ts)纳入 Git 选定的实际已跟踪条目和未被忽略的未跟踪条目。`stateHash` 对带分帧的索引记录、排序去重后的仓库相对路径，以及条目类型、文件内容摘要和普通文件可执行位求哈希。缺失的已跟踪路径贡献删除记录。HEAD 仍是 `dsh-source-fp-v2-<headCommit>-<stateHash>` 的独立组成部分。`entryCount` 统计选定路径，包括已跟踪路径的删除。

[启动命令](../../../../packages/experimental/command-goal-binding/src/composition.ts)使用完整状态哈希派生 `snapshot-v2-<headCommit>-<stateHash>`。完成时将存储指纹与新计算结果比较。因此，未暂存变化，以及未被忽略的未跟踪文件的新增或修改，无须暂存或提交就会使已记录源码失效。[完成准入决策](../architecture/2026-09-06-goal-completion-admission-seam.zh.md)继续拥有证据合取和原生 Goal 完成；本决策定义其使用的源码观察。

文件字节保留原样：行尾变化会改变源码证据。时间戳用于检测观察期间的变化，但不进入摘要。符号链接贡献链接目标文本，不读取所指向内容。符号链接祖先目录、包括缺失 Git 链接在内的子模块、特殊文件类型、非 UTF-8 路径、不可读条目，以及观察到的并发变化都会明确失败。被忽略的未跟踪路径和空目录仍不在选定源码范围内。

源码内容通过有界内存流式读取。`maxOutputBytes` 保持限制每次 Git 输出的含义；可选的 `maxSourceBytes` 限制源码内容的累计字节数，默认不施加累计上限。取消和配置的文件读取截止时间会停止所拥有的工作并关闭其资源。这些检查是观察，不是原子的文件系统快照，也不能替代调用方的写入所有权。

## 考虑过的替代方案

**只使用 HEAD 和索引记录。** Git 提供紧凑的规范表示，无须读取工作树，但未暂存和未跟踪源码发生变化时该表示仍可能完全相同。完成契约要求这些变化使证据失效。

**通过已暂存的 Git blob 进行规范化。** clean 过滤器和行尾规范化能改善不同检出之间的相等性，但所得字节可能与检查和工具实际读取的内容不同。使用工作树原始字节保留这种区别，不把源码规范化视为证据等价。

## 影响

验证读取全部选定源码内容，不只依赖 Git 元数据。字节上限、截止时间和忽略文件策略仍由宿主明确选择。两个检出即使 HEAD 和索引相同，也可能因实际文件字节或可执行模式不同而具有不同指纹。版本一指纹无法与版本二结果相等；引擎不会默默重新解释旧证据。

符号链接所指向内容的变化和被忽略文件的变化不在该指纹的声明范围内。若宿主的检查依赖这些外部输入，就需要为其提供单独证据。写入所有权必须贯穿观察及使用观察结果的操作；哈希不能使并发文件系统修改变成原子操作。
