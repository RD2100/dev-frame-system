# Agent Note：命令必需检查持久化

Status: implemented

[English](2026-09-07-persist-command-required-checks.md) | 中文

## 问题

命令组合能从 Session 日志恢复 Goal 及其验证证据，但挂载的插件选用了内存必需检查存储。冷重启后，完成流程能读到记录的检查清单摘要，却找不到对应的已批准命令。既有[文件后备存储](../architecture/2026-09-06-required-checks-file-store.zh.md)提供了持久化能力，但[宿主命令组合](../architecture/2026-09-06-command-goal-binding-host-command-surface.zh.md)没有选用它。

## 决策

挂载的命令插件要求提供非空、无首尾空白的绝对路径 `requiredChecksPath`，并通过组合已有的存储覆盖入口注入 `FileRequiredChecksConfigStore`。程序化组合保留该覆盖入口。插件激活会校验路径，但不会创建父目录或登记当前清单。启动 Goal 时按规范摘要保存已批准配置；完成时解析已归属到 Goal 证据的摘要。

操作者须预先创建父目录，把账本放在参与指纹计算的源码工作树之外，并在部署重启后复用同一路径。首次登记可以创建账本，但完成流程会拒绝账本缺失、历史摘要不存在或登记损坏的情况。部署检查清单的变更不会替代历史批准。交付和集成读取方在解析该证据时使用同一账本。

## 已考虑的替代方案

**在启动或查找缺失时登记当前清单。** 新部署配置无法证明先前 Goal 获准执行什么。保留历史登记才能让批准与记录的摘要绑定，并使状态缺失可见。

**另建命令专用持久化格式。** 既有存储已经拥有摘要校验和文件发布职责。在插件边界选用它可避免第二个账本所有者。

## 后果

[命令包配置](../../../../packages/experimental/command-goal-binding/README.zh.md#use-this-package)拥有操作说明。部署须保留现有证据需要的登记，指定单一写入者并串行执行保存。文件存储不会创建目录、合并并发写入或提供跨进程锁，也不保证 fsync 持久性。

冷重启验证必须在恢复的 Session 证据和同一账本上重新挂载命令插件，并覆盖部署清单已变更但仍合法的情况。完成流程必须解析原有批准；账本缺失和损坏时必须拒绝完成。这些用例可区分持久化插件接线与跨实例保留内存存储的测试。

ACP 录制场景先关闭第一个进程，再在第二个进程中恢复同一持久化 Session。其 fixture 执行真实 Git 检查和读取文件的脚本审查者，再调用公开的恢复与完成命令。快照 harness 固定恢复请求头、保留两个进程的协议记录，并在将工作区派生的检查清单哈希替换为 token 时保留相等关系。该 fixture 不证明自主模型审查或 SDK 恢复支持。
