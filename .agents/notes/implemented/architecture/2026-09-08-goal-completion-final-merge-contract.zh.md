# Agent Note: Goal 完成锚定于最终合并结果

Status: implemented

[English](2026-09-08-goal-completion-final-merge-contract.md) | 中文

## 问题

Goal 完成与最终合并是断开的两份契约。完成准入以 Goal 启动时记录的指纹校验实时工作树，并消费会话日志里最新的一条审查。当 `project_integrate` 把各绑定任务的已审工作合并进 controller 工作树后，树已越过该初始指纹：诚实的合并态永远无法对它完成；而把完成指向一棵陈旧树则能在完全未覆盖合并结果的情况下通过。没有任何机制把完成与集成域的已应用回执挂钩，单条任务审查也可以顶替最终合并审查。

## 决策

完成在既有合取之外获得显式的最终合并通道。`CompleteGoalRequest.finalIntegration` 携带持久证据：每个绑定任务一条已应用集成回执、持有合并树指纹的 whole-Goal 验证、以及 whole-Goal 审查。证据形态本已支持——`deliveryId` 缺省即 whole-Goal 记录，与任何绑定单次交付的任务级证据相区分。新的 final-integration 阶段在常规合取之前校验契约：回执必须恰好覆盖绑定的任务集，两条记录必须都是 whole-Goal，二者必须携带同一工作元组，且最终审查的 Session 必须异于每个绑定任务的交付 worker。

指纹阶段诚实重锚。最终合并通道下，准入以 whole-Goal 验证携带的合并树指纹重算实时工作树——绝不对绑定初始启动声明，绑定记录本身永不被改写；初始指纹仍是启动授权，最终态经由证据锚定。提交的审查必须是契约的审查，提交的检查摘要必须是契约验证的摘要，故没有调用方证据可以脱钩搭车。普通通道不变：无契约时完成照旧锚定初始指纹——在已移动的树上这如今是可证的拒绝，而非静默通过。

project-controller 的 `selectGoalCompletionIntegration` 是诚实构造器：只读持久集成行与会话投影的 whole-Goal 记录，要求每个绑定任务的回执已应用，缺证即以命名门 fail-loud。证据质量失败——未通过的审查、worker 签发的审查、陈旧指纹——留在准入里作为拒绝数据，而非抛错。

## 已考虑的替代方案

**集成后改写绑定指纹。** 静默重绑会让旧准入原样通过，同时洗白授权源；契约改为经校验证据重锚并保持绑定不动。

**把任务级 lead 审查当作最终门。** 那些审查在集成前评判的是各 Worker 分支，无一审视过合并结果。whole-Goal 形态（`deliveryId` 缺省）加 worker 独立性使这种顶替在结构上不可能。

**无条件要求最终合并证据。** 每个 Goal 绑定都有任务 id，硬性要求会在调用方接线完成前打断所有既有普通完成；通道由证据选择启用，普通通道的移动树拒绝已经把初始声明挡在最终态之外。

## 后果

devframe 套件钉住正向路径（以合并指纹完成、原生 Goal 完成、存储声明不动）、worker 审查拒绝、delivery-bound 顶替拒绝、覆盖拒绝、幻影指纹对实时重算的拒绝、普通通道移动树拒绝、证据身份守卫。project-controller 套件钉住从已应用回执与 whole-Goal 证据选取契约及每个命名缺证。命令面的拒绝渲染器按其闭联合并集要求补入 final-integration 用例。
