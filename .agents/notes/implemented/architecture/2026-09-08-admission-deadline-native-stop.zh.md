# Agent Note：准入截止调用原生项目停止

Status: implemented

[English](2026-09-08-admission-deadline-native-stop.md) | 中文

## 问题

前置步骤截止无法取消已经获准的工作。[准入截止提案](../../proposed/architecture/2026-09-06-at406-deadline-admission-seam.zh.md)保留仅截止契约及墙上时钟决策；其中暂缓的取消范围需要持有活动资源所有权，才能调用既有项目停止协议。

## 决策

`AdmissionCutoff.stop` 可选地为一个准入代际提供原生 `StopProjectOptions`。服务调度 epoch 截止，在调用停止前关闭准入，并通过 `deadlineStopResult` 暴露触发后的结果。既有停止协议负责取消、身份检查、刷新及有条件的写者释放。失败或不确定的清理保持 `needs_attention`。

重新打开和显式关闭会解除尚未触发的截止。已触发的停止仍持有清理权时拒绝重新打开；销毁会解除定时器并等待清理。长截止在 Node 定时器上限内重新调度，并复查墙上时钟。宿主为真实活动资源提供经过验证的部署配置及适配器。省略 `stop` 保留仅前置步骤的限制。

## 考虑过的替代方案

**独立的截止取消协议。** 复制停止逻辑会让截止到期与显式停止采用不同的身份、持久化和写者释放规则。

**清理期间允许重新打开。** 旧停止可能在新代际开始后释放所有权。重新打开必须等待旧结果。

## 后果

定向定时器测试覆盖代际替换、长延迟、销毁及清理失败。进程树旅程使用真实时钟及真实子进程、孙进程，观测截止触发取消，并在释放前确认退出。这些验证服务机制；完整 AT4-06 验收还需要宿主的真实资源适配器、配置和项目生命周期。
