# Agent Note: 关联 worktree 的宿主授权提交

Status: implemented

[English](2026-09-08-host-worktree-commit.md) | 中文

## 问题

关联检出将索引存放在检出目录之外，并与锚点仓库共享 Git 对象和分支引用。仅获准写入检出目录的 Worker 无法完成 Git 提交。授予 shell 对共享 Git 目录的访问权，也会暴露其他分支和 worktree。

## 决策

[worktree 注册表](2026-09-05-worktree-registry.zh.md)提供仅限宿主调用的提交操作，输入包括已登记的 worktree ID、匹配的 holder、完整的预期 HEAD、明确指定的相对文件路径和提交消息。它将操作与注册表变更串行执行，固定经验证的 Git 目录，拒绝已有暂存改动，并检查结果提交的唯一父提交是否为预期 HEAD。

消费者负责授权请求、从调用会话的绑定派生 holder，并使其他写入者停止写入。注册表的[单写者绑定](../feature/2026-09-05-per-agent-worktree-single-writer-seam.zh.md)不能阻止任意文件系统写入。该服务不授予额外 shell 能力，也不提供面向模型的工具。

宿主提交禁用 hooks、签名、文件系统监视器和自动维护；带有 filter 属性的已跟踪或选定文件会被拒绝。缺失路径必须精确指向已跟踪文件；选定路径中的符号链接和 junction 会被拒绝。取消或失败可能留下暂存改动或已完成的提交，因此消费者应在重试前检查索引和 HEAD。结果区分新提交 ID 与整个检出的干净状态。

## 考虑过的替代方案

- 仅授予单个 worktree 的 Git 目录访问权并不足够，因为提交还会写入共享对象和分支引用。授予整个公共目录访问权会暴露无关仓库状态。
- 独立克隆消除了共享元数据需求，但不能保留关联 worktree 的登记与对账语义。
- 在宿主提交中运行检出的 hooks 或 filters，会使检出控制的程序在 Worker 的执行边界之外运行。

## 后果

受信任的消费者可以提交选定的 Worker 产物，同时保留检出的 shell 边界。它们必须提供授权和写入静默条件、处理不确定结果，并经既有验证路径运行必需检查。依赖提交 hooks 或文件 filters 的仓库流程不能原样使用该操作。
