# Agent Note: 总控 Git 集成恢复

Status: implemented

[English](2026-09-07-controller-git-integration-recovery.md) | 中文

## Problem

任务状态更新不能证明 Git 已改变目标工作树。Git 与任务存储无法原子提交，因此进程中断可能留下没有任务回执的成功合并。重复执行结果不确定的合并，可能操作已经变化的目标，或覆盖原始尝试的含义。

## Decision

[项目总控](../../../../packages/experimental/project-controller/README.zh.md)将每次准入绑定到精确的源提交和目标提交、已注册的总控与 Worker 工作树，以及持久化的验证和独立评审证据。最新 Goal 必须开放准入且包含该任务；已停止或被取代的 Goal 中的通过证据不能授权集成。它在启动快进合并进程前立即重新检查当前证据、所有权、锁、取消状态和生命周期。宿主持续独占目标直到回执记录完成；注册表锁不能排除无关的外部 Git 进程。

总控在 Git 执行前持久化 prepared 意图，并在 integrated 任务状态前写入 applied 回执。协调恢复会观察目标，在合并已应用时补齐记录，而不再次调用合并。含糊的观察结果需要处理。只有通过显式重试和重新准入，未变化的目标才允许再次尝试；旧的进程内标记不能授权该次尝试。取消不代表 Git 没有改变目标。

独立的 Loader 消费者从宿主注册表推导身份和工作树路径。模型参数仅包含任务和请求的动作。Git 进程限制和检查登记文件属于宿主配置。消费者与现有服务共同挂载，不创建第二个总控。

任务规划与开发准入通过独立的根 controller 消费者操作同一任务板。宿主在每次串行写入内部重新检查权限，因为排队前的授权可能在其他任务占用队列时失效。开发准入先于 briefing 投递；部分失败后仍以任务板为准，不允许自动重试而重复发送 Worker 指令。

任务交付保留不可变的 Goal 输入绑定，并单独记录带身份的输出版本。验证与独立 lead 审查引用同一最新交付，避免开发后的提交被当作新的 Goal 确认，或借用其他任务的通过证据。检查必须实际执行已批准配置；失败或中断后的重跑由调用方明确请求。证据 journal 与任务板不能原子提交，因此相同的已记录审查可用于补写任务状态，而不能被解释为再次批准。

## Alternatives considered

- 仅凭标记改变状态可以证明授权，但不能证明文件系统结果。
- 超时后自动重试把缺少确认当成未执行的证明。
- 只持久化最终任务状态会丢失区分已应用合并和未开始尝试所需的边界。
- 重置目标来重试会丢弃用户或总控的独立工作。

## Consequences

持久化意图使中断的集成可以恢复，但不能使 Git 和存储成为原子操作。prepared 意图以及任务仍为 submitted 的 applied 回执都是合法恢复状态。宿主必须先协调恢复不确定结果，再调度其他目标写入。只接受干净、独立的工作树和快进变更；冲突需要另行处理。

包内真实 Git 和 Loader 测试覆盖权限拒绝、证据变化、显式重试、忽略文件冲突保护、取消、释放以及回执和任务写入中断。模型会话录制覆盖与部署激活是独立于这些测试的证据。版本化任务域拒绝旧格式；此决策不授权重置现有生产域。
