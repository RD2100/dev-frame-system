# Agent Note: 有边界的插件化 Agent 组织与调度

Status: proposed

[English](2026-09-05-pluginized-agent-topology-and-dispatch.md) | 中文

## Problem

当前项目计划需要协调许多低耦合能力，但项目总控、插件组长和叶子 Worker 容易被误解为不同类型的 Session，或者只用 UI 标签表示。这种歧义使 SessionID 所有权、工作树所有权、子 Agent 权限、恢复责任和合并责任都难以验证。

开发计划还把平台基础、现成第三方插件和后续多项目想法混在一起。没有明确的插件所有权和有界创建深度，并发开发可能重复安装、覆盖共享文件、耗尽 Provider 配额，或者让一个没有持久化证据的任务看起来仍在运行。

## Proposal

定义一个三层有界结构：L0 是一个一等项目总控 Session，L1 是一等插件组长 Session，L2 是不能继续创建 Agent 的叶子 Worker Session。总控和组长使用同一套 Agent/Session 机制，每个都有持久化 SessionID 和独立工作树，父子关系保存为授权和展示元数据。

只允许总控创建组长，只允许组长创建属于自己插件 ID 的 Worker。在工具分发、冷恢复和伪造请求路径都执行该规则，创建边最多两条，不允许递归创建。

把实现拆成独立负责的插件接缝：SessionID、层级、工作树注册、总控调度、证据、可靠性、UI、显式外部 Agent 路由、Provider 接入和可选扩展。只保留一个很小的共享契约库作为唯一有意的跨插件源码依赖。

总控是主树唯一合并负责人。组长可以在自己的工作树提交并申请审查；QA 在精确路径提升前，先验证一份固定组合候选。

## Alternatives considered

**A. 只有一个总控加内部标签：** 否决，因为标签不会产生独立 SessionID、工作树所有权或可执行的组长权限。

**无限递归创建 Agent：** 否决，因为它让配额、所有权、恢复和终止都没有上限，也允许叶子 Worker 在职责范围外继续派生工作。

**给插件组长设置更弱的特殊 Session 类型：** 否决，因为用户需要组长独立创建 Worker 并恢复；让组长使用一等 Session 可以保持身份和生命周期模型统一。

**一个单体式编排插件：** 否决，因为它会耦合 Provider、UI、移动端、可靠性和项目功能，也无法支持独立 Agent 所有权和安全并发。

## Acceptance criteria

运行时可以创建一个总控、多个一等组长和有边界的 Worker；每个都有唯一持久化 SessionID、精确父级记录和一条 Agent/工作树绑定。

Worker 创建 Agent、组长创建组长、超出深度、重复所有权、伪造父级数据和歧义工作树路径等尝试，在在线和冷恢复路径都 fail closed。

Web UI 使用同一套记录渲染折叠的总控 → 组长 → Worker 树；每次箭头操作只展开一层，并且无需对话框即可直接复制完整 SessionID。

总控可以并发调度独立插件，串行处理共享契约/profile/主树集成，处理重启和限流，并且只合并经过审查的精确路径。

本次指定的五个现成仓库由一个隔离的验证组长负责验证；认证/配额跳过必须如实记录，不能污染生产 profile。

## Risks

该结构会增加持久化注册表和事件字段，因此必须在大规模插件开发前规划事件所有权、会话日志恢复和 schema 演进。

有界深度有意放弃任意深度委派；未来如果需要更深流程，必须重新设计和审查，不能静默提高限制。

独立插件仍会竞争共享 Provider 配额和 profile 文件；总控必须明确控制并发和集成队列。

第三方兼容性、认证、配额和许可证仍然是外部风险；仅凭本地 profile 加载成功不能把它们变成绿色证据。
