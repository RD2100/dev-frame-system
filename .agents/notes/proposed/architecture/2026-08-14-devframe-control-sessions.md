## Problem

DevFrame needs one durable Global Controller and one durable Project Controller per DSH Workspace before it can safely dispatch agents, but a random chat is not a durable authority and a second workbench or database would split authority from DSH. This note is the Slice 0 entry ledger: it records what the fixed DSH commit actually exposes, what is only a candidate in the dirty working tree, and the smallest missing seams before control-plane execution can be enabled.

## Proposal

Reuse DSH's native Workspace, Session, Agent, Goal, Job, Workflow, provider, tool, persistence, Profile, Bundle, and UI seams. Add only a thin DevFrame control layer that binds a deterministic Global identity `devframe-global:<profileId>` and Project identity `devframe-controller:<workspaceId>` to DSH Session logs, then exposes readiness and a single native Global entry. Do not add a second Session database, second chat model, second terminal, second project registry, or a wholesale Agent Loop rewrite.

The first accepted slice is identity and readiness only. It must write and flush one validated `controller/identity` event before model or tool execution, keep Global read-only and project-free, and fail closed when identity, Host ownership, provider readiness, or policy evidence is absent. Dispatch, revision loops, paper workflows, Obsidian writeback, MCP bridge, and browser interaction remain later slices with their own gates.

This is a commit-backed Recon Receipt, not an implementation approval. Screenshots, README claims, old DevFrame code, and current candidate UI are not upstream evidence; candidate evidence is labelled separately below. The status therefore remains `proposed` and `review-pending`, never `PASS`.

## Target

The target is the smallest usable control-plane foundation inside DSH: a user can open one Global Controller, see its exact Session identity and readiness, select a Workspace, and later hand a governed task to a Project Controller without creating another authority. Slice 0 does not promise autonomous project edits, browser automation, paper drafting, or multi-agent completion.

## Core Concepts

- Workspace is DSH's durable project registry and canonical path owner; DevFrame binds a Project Controller to its stable Workspace ID, never to a raw path.
- Session is the durable event log and identity boundary; DevFrame must use the exact DSH Session ID and `SessionStore.flush` barrier.
- Agent is the live executor registered against a Session; `Agent.id === Agent.session.id` remains a DSH invariant, not a second DevFrame identity.
- Goal, Job, and Workflow are useful native execution primitives, but their current scope is process or session local and none is the final controller verdict.
- Model and provider settings remain DSH-owned; DevFrame supplies routing and policy metadata, not a new model database or provider implementation.
- File, Shell, Terminal, Diff, web search, and web fetch are native tools with different isolation and evidence properties; `web_fetch` is not a DOM browser.
- Global Controller, Project Controller, Control Roster, Task Board, Evidence Store, Review, MemoryGateway, Paper Domain Pack, and Host MCP bridge are DevFrame additions that must be layered above these seams.

## Core Data Models

| Object | Required identity or fields | Authority and persistence rule |
|---|---|---|
| Global Controller | `sessionId = devframe-global:<profileId>`, `profileId`, role `global`, schema version, canonical cwd | DSH Session log plus Host readiness; no project tools or Project Verdict. |
| Project Controller | `sessionId = devframe-controller:<workspaceId>`, `workspaceId`, role `project`, canonical Workspace cwd | DSH Workspace and Session log; one Project Controller per Workspace. |
| Run | `runId`, `agentSessionId`, `roleAssignmentId`, `taskId` | Created only after Controller authority and policy gates exist. |
| Message Envelope | `messageId`, `sessionId`, `runId`, sender, recipient, kind, payload reference, attempt, timestamp | At-least-once delivery with idempotent claim; raw prompts and credentials stay behind the API boundary. |
| Evidence | `evidenceRevision`, source event IDs, diff or test references, reviewer decision | Evidence is append-only and cannot be replaced by a UI status label. |
| Readiness | profile identity, Host lease, persistence, provider, authority, required tools, MCP and memory state | A conjunction of explicit checks; missing evidence is `blocked`, not `ready`. |

## Acceptance criteria

1. A real DSH Profile/Bundle boot from an empty temporary home opens the native client with one DevFrame Global entry and no second service command.
2. Starting from cwd A, disposing, and restarting from cwd B restores the same Global Session ID; reopening a Workspace restores the same Project Controller ID.
3. Each controller Session has exactly one valid first `controller/identity` event and its creation returns only after an awaited persistence flush.
4. Concurrent opens in one Host publish one live Agent and one Session log; corrupt or mismatched identity fails closed without replacement authority.
5. The ordinary tree has no duplicate Global row, the chat has no identity card, and the menu copies the exact Host-published Session ID.
6. Global's effective tool set contains no project File, Shell, Terminal, or Browser capability.
7. Project write dispatch is blocked until Authority, PolicyDecision, ContextPacket, Evidence, Reviewer, and HumanGate gates are present.
8. Cross-Agent and cross-Session messages have stable IDs, at-least-once claim, idempotence, and durable evidence references.
9. Focused per-capability probes, `SessionEventMap`/known-event/persistence-catalog generation, the matching Conversation Node projection decision, package invariants, typecheck, real Loader/Profile composition, restart, duplicate-writer, and negative identity probes pass on a clean checkout.
10. License, secret, privacy, browser-provider, MCP, and Obsidian publish gates are recorded before their slices are accepted.

## Risks

The public Agent API does not expose an atomic cross-process restore-or-create helper; the identity adapter must keep serialization narrow and prove duplicate-writer behavior.

Jobs, Workflows, and PTYs have process-local lifecycle limits; restart state must be represented in Controller events rather than inferred from live objects.

Local Shell and File providers are not containment by themselves; role-scoped tools and sandbox policy are mandatory before project writes.

DSH event data can reach the browser through the Host API; identity events must be bounded and must never contain credentials, prompts, or extra paths.

A provider switch or MCP bridge can leak secrets or create a second writer; record only non-secret IDs and keep the canonical Host as the writer.

Profile UUID cannot be derived from telemetry anonymous ID, cwd, or a temporary value; absent or invalid explicit profile identity must block readiness.

Browser and Obsidian additions are separate risk domains and remain blocked until independent Recon, license, privacy, and human-gate evidence exists.
