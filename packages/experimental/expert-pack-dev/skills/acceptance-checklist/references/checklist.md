# 验收检查单

按产物类型选取适用的条目组；同一份产物可命中多组。每项的结论是"通过 / 不通过 / 无法判断"之一，并附一行依据（指向具体条目或小节）。

## 通用条目（任何验收标准）

- [ ] 每条标准可独立判定：给出可观察的结果，能被"是/否/多少"类答案检验。
- [ ] 没有无法判定的措辞："合理""尽量""友好""快速"这类词要么改写成可观察结果，要么降级为开放问题。
- [ ] 每条标准有明确的适用对象：说清对什么、在什么条件下判定。
- [ ] 标准之间不互相矛盾；冲突的条目被显式指出并交由上游或人类决定。

## PRD 验收标准（prd.md）

- [ ] 每条验收标准标注所属用户故事；没有故事归属的标准说明来源或删除。
- [ ] 每个用户故事至少有一条验收标准；覆盖不到的故事被列出来。
- [ ] 非目标一节明确排除的内容与功能范围没有重叠。
- [ ] 无法从运行请求材料确定的标准进入开放问题，不写成断言。

## 任务验收标准（tasks.md）

- [ ] 每个任务都有可判定的验收标准；没有标准的任务被显式列出并说明缺什么。
- [ ] 任务验收标准能追溯到 PRD 验收标准或 design.md 的接口契约；追溯不到的说明来源。
- [ ] 依赖关系构成 DAG：没有相互等待的任务环。
- [ ] 跨任务的公共约定有明确归属，不留给实现者自行发明。

## 测试映射（test-report.md）

- [ ] 每条验收标准至少映射到一个测试项，或显式标注"未覆盖"及原因。
- [ ] 每个通过的结论都有证据：测试命令与输出摘要。
- [ ] 缺陷报告每条都有复现步骤、期望结果与实际结果；复现不了的如实标注。

## 诚实边界（交付前最后一遍）

- [ ] 没有"测不了所以算通过"的条目；测不了就是未覆盖，写明原因。
- [ ] 改写过的标准逐条回应了驳回批注；未被批注授权的范围没有被改动。
- [ ] 需要人类决定的事项全部进入开放问题，没有静默丢弃。
