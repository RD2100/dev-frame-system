## DSH web 服务启动失败排查（桌面快捷方式"DSH 启动服务"）

- 现象：双击桌面图标无反应/打不开。真实原因两层：
  1. `~/.dsh/profiles/web/cordis.patch.yml` 手工 insert 的 `project-memory` 行缺必填 `workspaceId`，插件树加载失败 → 进程启动后立刻退出。
  2. 同一补丁里的 `shadow-router` 硬注入 `agentBindings`（只有 `experimental/session-identity` 提供），web profile 未挂载 → 1 entry did not activate，主机在监听后仍退出。
- 处理：给 `project-memory` 补 `workspaceId: dsh-devframe`（安全路径段即可，仓库默认值是 `default`）；把 shadow-router / shadow-controller / ui-shadow-entry 三行注释掉并写明原因（正确做法是挂 devframe-profile 层：`pnpm dsh --profile web --patch ./packages/experimental/devframe-profile/cordis.patch.yml`，不要手工 insert 单行，会 duplicate-id）。
- 附带修的 UX 坑：`dsh web` 每次启动生成一次性 launch token，裸开 `http://127.0.0.1:3080/` 返回 401 "authentication required"。已重写桌面脚本 `C:\Users\25313\Desktop\DSH 启动服务.ps1`（原文件备份为 .ps1.bak）：node 输出重定向到 `%TEMP%\dsh-web.out.log` / `dsh-web.err.log`，从输出里正则抓 `dsh web: <url>` 再打开；监听后等 3 秒确认进程存活；失败弹 MessageBox 并附错误尾部。
- 环境注意：本会话里 PowerShell `Start-Process` 带 `-Redirect*` 时返回空 PID 且子进程不起；`cmd //c start`、直接跑 .ps1（执行策略全 Undefined）也起不来。可用方式是 Bash 工具 `run_in_background` 跑 node（会话结束可能被回收，长期运行应让用户双击桌面图标）。
- 验证：3080 LISTENING，`/?token=...` 返回 303，服务稳定。

## 桌面脚本 bug 修复（双击后弹"找不到参数 join"）

- 用户双击图标后弹 MessageBox：`DSH 启动失败 / 找不到与参数名称 "join" 匹配的参数`。表面是参数 join 错，根因有两层：
  1. **真正错误**：`dsh web` 收到只剩两个值的 argv（`./packages/.../cordis.patch.yml`、`C:/.../devframe-deployment.yml`），报 `error: too many arguments. Expected 0 arguments but got 2`。原因：ps1 里 `Start-Process -ArgumentList (@(...) + $patchArgs + '--no-open')` 用 `+` 拼数组，PowerShell 参数绑定把 `--patch` 这类标志吞了。修法：换成 .NET `ProcessStartInfo.ArgumentList`（逐项 Add，无 shell 解析），并把整段 argv 写成一个 `[string[]]@(...)` 字面量，不要 `+` 拼接。
  2. **错误显示也被破坏**：失败提示里有 `($tail -split "`n" | Select-Object -Last 25 -join "`n")`，`-join` 紧跟 `Select-Object` 后被 PowerShell 解析成 `Select-Object` 的命名参数（不是 -join 运算符），所以失败分支自己也抛了 "join" 异常，**把真正该展示的 dsh 报错完全盖住**。修法：把 `-join` 移到数组表达式外（`($lines | Select-Object -Last 25) -join "`n"`），让它是二元运算符。
- 顺手把 stdout/stderr 的落盘改成独立 `Start-Job`（runspace 里 `ReadLine()` 循环写到文件），不再用事件/ScriptBlock 写文件——这样启动器退出后台任务也不会被回收，子进程管道也不会因为 launcher 退出而死锁或 EPIPE。
- 教训：PowerShell 启动器里传多参 argv，**绝对不要 `+` 拼数组**；失败提示里 `-join` 一律放表达式外侧；二者踩一次都很难定位。

- 坑：Windows PowerShell 5.1 用 `-File` 跑无 BOM 的 UTF-8 脚本会按 ANSI(GBK) 解码。桌面脚本已改为 UTF-8 with BOM；解析校验用 `[Parser]::ParseFile`（默认编码）才准，`ParseInput` 配 UTF8 读会把编码问题藏掉。

## 第三轮：服务起来了但页面 404（"还是不行"）

- 现象：3080 在听、token URL 正常打开、`/?token=` 返回 303 并下发了 cookie，但带 cookie 的 `GET /` 返回 **404 空 body**。`dsh-web.err.log` 是空的，插件树无激活失败。
- 根因：**`apps/web/dist` 不存在**。SPA 由 `web-runtime`(`@deepseek-ai/dsh-web-app`) 挂的 `frontend-static` 提供，它 `distIndex = packages/bundle/web-app` 里 `require.resolve('@deepseek-ai/dsh-web-frontend/package.json')` 的目录 + `dist/index.html`，即 `D:\dsh-devframe\apps\web\dist\index.html`。`serveStatic` 在读 index 时 ENOENT → 落进它的 404 分支。
- 关键认知：**dist 缺失不会让启动失败**。`packages/host/frontend-static/src/index.ts` 每请求才 `readFile(distIndex)`（源码注释：dist 存在性是 request-time concern），所以服务照常起、照常打印 token URL，唯一症状就是页面 404。同理 `webserver` 的 `fallback === undefined` 也会 404，两者要区分。
- 修法：`apps/web` 下 `node ./node_modules/vite/bin/vite.js build`（约 6s，产物 26KB 的 index.html；pnpm 的 `node_modules/vite` 软链在 `.pnpm` 里，根目录没有实体包，别用 `node_modules/vite/bin/vite.js`）。**不需要重启服务**——改完立刻 200/26974 bytes，与正常基线一致。
- 桌面脚本加固（已写进 `DSH 启动服务.ps1`）：启动前检查 `apps/web/dist/index.html`，缺失就用脚本自己找到的 `$node` 跑 vite build，失败弹框并给出可直接照抄的手动命令。这样 `pnpm run clean`／切分支后双击图标不会再变成 404。
- **token 是每进程一次性的**：脚本复用"已在运行的"服务时抓不到新 token，会拿日志里的旧 token → 401。已改为启动时把 `PID=` / `URL=` 写进 `%TEMP%\dsh-web.token`；复用分支只在文件里的 PID 与当前 3080 的 owner PID 一致时才用，否则弹提示说明"请用该服务启动时打印的带 token 链接，或结束该 PID 后重开图标"，而不是静默打开一个 401 页面。
- 工具环境限制（会影响验证，不代表脚本有问题）：**PowerShell 会话里 `& node.exe ...` 被静默拦截**——无输出、`$LASTEXITCODE` 为 $null；`Start-Process powershell.exe` / Bash 里调 `powershell.exe` 也被安全策略拦。所以桌面脚本无法在工具内端到端跑通，只能靠 `[Parser]::ParseFile` 验语法 + 用 Bash 直接起 node 验服务。Bash 里跑 node 是允许的。
