# 详细设计第 1 部分：单项目开发

[English](detailDesign-part1.md) | 中文

## 概述

本文定义[总体设计](generalDesign.zh.md)的首个实施阶段。项目控制器拥有一个原生扁平 Team，包含一个开发者和一个只读审查者。DSH 负责执行与团队状态，DevFrame 增加角色限制和小型完成校验。下文所有 DevFrame 工具名称和新增数据均为拟议设计，不是现有公开 API。

## 需求与输入

控制器接收用户批准的项目根目录、具体任务、允许修改的范围和必需检查。检查命令来自用户或现有可信项目配置；不可信文档不能悄悄注册新的可执行检查。

在接收运行时解析并固定必需检查编号、命令定义和快照排除项。开发者不能通过编辑项目配置降低这些要求；改变已接受检查清单需要新的明确用户决定，并使受影响证据失效。审查还必须检查测试代码或脚本的变化是否削弱覆盖。

| 编号 | 必要行为 | 验收位置 |
| --- | --- | --- |
| `R1.1` | 在创建、执行和冷恢复时实施各角色的工具访问限制。 | [AT1-01、AT1-02](testAndAcceptance.zh.md#part1) |
| `R1.2` | 以单个活动写入者实现任务，并采集真实检查结果。 | [AT1-03、AT1-04](testAndAcceptance.zh.md#part1) |
| `R1.3` | 只验收经过测试和审查的源码快照，并拒绝绕过。 | [AT1-05、AT1-06](testAndAcceptance.zh.md#part1) |
| `R1.4` | 复用原生组合、成员生命周期与有界续跑。 | [AT1-07、AT1-08](testAndAcceptance.zh.md#part1) |
| `R1.5` | 连续目标与恢复期间，保持任务、证据和预算归属正确。 | [AT1-09](testAndAcceptance.zh.md#part1) |
| `R1.6` | 让用户不经模型代为批准，即可配置、开始、停止、恢复和检查单个项目。 | [AT1-10](testAndAcceptance.zh.md#part1) |
| `R1.7` | 测量连续真实任务相较直接单 agent 使用，是否减少用户操作负担。 | [AT1-11](testAndAcceptance.zh.md#usefulness) |

缺少验收范围时返回 `needs_input`，不自行发明产品需求。小型只读分析任务可以明确声明代码检查不适用，但代码修改任务不能悄悄用文字总结代替执行检查。

<a id="work-identity"></a>

## 工作归属与连续任务

对于明确启动的团队开发任务，一次项目运行对应控制器会话拥有的一个原生 Goal。稳定运行键为 `(controllerSessionId, goalId)`，不是新的 Run 记录或数据库。普通单 agent 工作可以留在常规 DSH 会话中，不进入此流程，也不创建 Goal。

| 字段 | 来源与关联规则 |
| --- | --- |
| `controllerSessionId`、`goalId` | 来自原生会话头与 Goal 身份；派发时固定，不在结果到达时按当时的当前 Goal 猜测。 |
| `taskIds` | 纳入本 Goal 的原生 Team 任务 ID，通过宿主拥有的会话事件关联；任务状态仍由原生任务行负责。 |
| `acceptanceHash` | 已批准目标、允许路径、必需检查定义和快照排除项的指纹；配置正文与指纹一起持久化。 |
| `snapshotId` | 验证时采集的输入内容指纹，不是任务或 Goal 身份。 |

验证与审查绑定完整元组 `(controllerSessionId, goalId, taskIds, acceptanceHash, snapshotId)` 及角色策略版本。任务集合变化后，旧集合的证据失效。旧任务板中的未完成项只有被明确纳入新 Goal 的必需依赖时才会阻挡它；不能把所有历史任务都当作完成前提。

原生 [Goal 身份与版本](../packages/goal/goal/src/types.ts)职责不同：ID 标识运行，`{ id, revision }` 通过比较后更新保护每次修改。暂停／恢复改变版本，不改变运行身份。恢复保留已消耗预算；只有重新确认元组一致且源码未变，才能保留证据。即使源码字节相同，验收要求改变也会让证据失效。

Goal A 验收通过后，明确的新启动创建 Goal B，并建立新的任务关联与预算；控制器和成员复用。未完成 Goal 应恢复，或在停稳后由用户明确放弃，不能悄悄替换。放弃会清除当前原生 Goal，但保留历史，不代表验收通过。A 的迟到结果仍归 A，不能满足 B 的验收或计入 B 的预算。

<a id="roles"></a>

## 角色与权限实施

角色名称是宿主定义的枚举值，不是模型任意选择的 persona（角色提示）。每个项目先使用以下角色；可选研究员和额外开发者暂缓引入。

| 角色 | 允许 | 拒绝 |
| --- | --- | --- |
| 控制器／Team Lead | 读取项目上下文、管理原生任务、分派后续工作、检查证据、请求项目完成。 | 直接修改项目文件、任意 shell 执行、无限制创建成员、自我修改和提权。 |
| 开发者 | 在批准的项目范围内读写文件、运行允许的开发命令、执行已配置检查。 | 修改其他项目、发布改动、改变角色策略或宣布项目验收通过。 |
| 审查者 | 读取源码、差异、需求和采集的检查输出；针对指定快照提交问题。 | 写入、shell、格式化器、生成器、后台任务、委派执行，以及验收自己修复的代码。 |

原生 `tools.restrict()` 过滤继承工具，不过滤当前作用域自行注册的工具；[作用域测试](../packages/core/tools/tests/scoped.spec.ts)明确覆盖此行为。[Team 工具](../packages/experimental/tool-agent-team/src/index.ts)注册在 `agent.ctx`，因此只传递子会话 `toolFilter` 不能完成角色限制。

| 机制 | 首轮验证采用的方式 |
| --- | --- |
| Profile 组合 | 使用 native 工具呈现，省略未使用的工作流、插件自我修改、外部执行器和任意 MCP 插件；不暴露原始面向模型的 Goal 修改入口。 |
| `tools.restrict()` | 按角色限制继承的文件／shell 工具；不将它用作本地 Team 工具的控制机制。 |
| `tools.guard()` | 在受管理 profile 注册单调拒绝检查，使用真实活动调用者和宿主恢复的角色；覆盖所有分派工具，包括本地作用域工具。 |

审查者可使用项目读取、`list_agents`、`team_task_list`、`team_task_get` 和 `project_review`；拒绝 Team 成员创建、任务修改、中断和工作分派。guard 同时拒绝未知身份、缺失策略和模型自行声明角色的尝试。后续前置执行允许决定不能覆盖 guard 拒绝。如果被禁用的本地 Team schema 仍然可见，它们仍在执行时被拒绝；隐藏这些 schema 需要修改注册位置，而不是再调用一次 `restrict()`。

项目根会话仅保留用户授予的项目执行范围，使开发者能够继承该范围。控制器面向模型的工具限制与这份可委派授权分开处理。不能先把父会话沙箱设为只读，再尝试给开发者提权；审查者获得更窄的访问范围，任何子会话都不能扩大继承的授权。

每个项目只有一个由宿主强制管理的写入所有者。其范围覆盖文件工具、shell 启动的进程、格式化器、测试进程和后台任务，直到它们真正结束。原生任务的 `writeScopes` 是描述性元数据，不是锁；锁转移和取消遵循[第 4 部分](detailDesign-part4.zh.md#stopping)。

只读审查是对 agent（智能体）工具与受支持执行适配器的限制，不证明 Windows 能阻止所有恶意同用户进程写入。[总体设计](generalDesign.zh.md#constraints)中的部署限制仍然适用。

<a id="execution"></a>

## 执行与验证

控制器把任务依赖与任务状态保存在原生 Team 任务板中。分派工作结束时任务可以变成 `completed`；这不等于项目的原生目标完成，也不等于通过验收。

1. 读取项目上下文与相关文件；记录原有未提交改动基线，不执行重置或 stash。
2. 创建最小且有用的原生任务，向开发者发送包含范围和必需检查编号的有界工作请求。
3. 必须启动的工作使用 Team `followup_task`。Team 的 `send_message` 是安静投递，不能把它当作唤醒操作。
4. 编辑结束后，开发者调用 `project_verify`；宿主运行已配置检查，并采集真实退出状态与输出。
5. 让写入者完全停稳，将准确的源码快照、验收范围、差异与检查引用发给审查者。
6. 审查要求修改时，恢复同一个开发者，让先前证据失效，并在修复次数限制内重新检查和审查。
7. 请求 `project_complete` 校验完成条件，并把实际结果返回给用户。

拟新增工具限定在会话范围内。每次调用携带 `goalId` 与 `acceptanceHash`；宿主校验调用者的派发关联，并在异步工作前固定其中的 `taskIds`。响应携带这些关联、有界摘要和证据引用。陈旧工作返回 `stale_work`，不能变成新 Goal 的证据。

| 工具 | `goalId` 与 `acceptanceHash` 之外的输入 | 宿主负责的输出与拒绝 |
| --- | --- | --- |
| `project_verify` | `checkIds`；调用者必须是活动开发者。 | 返回 `verificationId`、`snapshotId`、逐项退出状态、耗时和输出引用。未知检查、错误项目或没有写入所有权时拒绝。 |
| `project_review` | `snapshotId`、`decision`（`pass` 或 `changes_required`）和有界问题列表；仅审查者可用。 | 返回关联审查者身份、策略版本和快照的审查引用。未知快照或开发者冒充审查者时拒绝。 |
| `project_complete` | `snapshotId`；仅控制器可调用。 | 校验后取得同一 Goal 的当前原生 `GoalRef`，通过比较并交换完成；Goal 已变时拒绝，不悄悄对另一个 Goal 重试。 |

源码快照对相关已跟踪与未跟踪输入的字节内容生成指纹，包括测试、依赖锁文件和配置；只有 `HEAD` 不够。项目配置声明输出／缓存排除项。排除项之外的任何变化都让快照失效，包括运行期间的人工作业。

宿主在验证前后以及完成前再次检查快照。检查记录包含实际可执行文件、参数、工作目录、退出码和有界日志引用。模型写出的成功陈述、没有进程结果的测试数量或已取消命令，都不能生成通过证据。

<a id="completion"></a>

## 完成与失败处理

只有本 Goal 必需的 `taskIds` 已结束、所有必需检查与独立审查通过同一个当前工作元组、不存在阻断问题且没有活动写入者所属进程时，才允许完成。校验与原生目标转换在同一项目修改互斥范围内执行。原生阶段为 `complete` 但没有匹配证据时，结果是 `needs_attention`，不是项目验收通过。

功能在原生会话持久化中保存角色／策略身份、Goal 与任务的关联及批准配置、用量事件、验证和审查引用。这些是拟新增的插件所属事件记录，不是已有 DSH 字段；必须在开放接收前能够回放。源码快照和日志使用现有产物存储。状态仍由原生 Goal 与 Team 任务保有，不增加独立 Run 或验收数据库。

| 条件 | 必需响应 |
| --- | --- |
| 检查失败、跳过或超时 | 保持目标未完成；展示失败检查与可用输出。 |
| 审查要求修改 | 在配置的修复次数内交回开发者；每个新快照都需要新证据。 |
| 达到修复／成员／请求限制 | 停止自动续跑，请求人工作出决定；不通过新建成员绕过限制。 |
| 持久化失败 | 不宣布验收完成；在状态重新可读之前阻止后续修改。 |
| 用户改变验收范围 | 记录新的用户指令，让受影响证据失效；不把旧失败重新解释成通过。 |

<a id="integration"></a>

## DSH 集成

[原生子会话组合](../packages/subagent/subagent/src/child-agent.ts)支持 persona／工具限制与持久化委派策略，但 [Team 成员管理](../packages/experimental/agent-team/src/roster.ts)没有传递全部相关选项。通过实验性 Team API 传递原生子会话选项是确需修改的源码部分；DevFrame 角色与策略保留在通用核心循环之外。

在恢复会话前安装 profile 级 `tools.guard()`。把角色／策略数据恢复到 guard 使用的同步查询中；数据缺失时拒绝执行。创建／设置路径在各个准确的 agent 作用域首次步骤之前应用 persona 与继承工具限制。冷恢复重复该设置；不序列化 disposer，也不假设上一个进程的 guard 仍然存在。只有所属工作停稳后才释放 guard。

模型步骤接收与工具权限分开处理：使用 `agent/pre-step` 拒绝已关闭或不匹配的工作关联，调用 `next()` 时保留下游拒绝。[第 4 部分](detailDesign-part4.zh.md#recovery)负责被拒绝输入的恢复。只有聚焦验收分别证明本地作用域 guard 拒绝、冷恢复和前置步骤接收生效后，才能声称集成有效。

首阶段优先创建新的可续跑队友，不使用完整历史 fork；控制器提供简短任务上下文。只允许直接子会话，禁用通用递归 spawn。复用成员，不按任务反复创建：原生 `maxMembers` 限制的是整个生命周期的成员表数量，也包含创建失败的成员，不仅是活动并发数。

使用[原生 presets](../packages/preset/agent-presets/README.zh.md)、作用域内的 Cordis effects，以及已记录的 `dsh --profile` 启动路径。新 profile／包的确切名称在实现时确定，本文不把它描述为已经可执行的命令。用户界面必须在现有 DSH UI 中展示任务、角色、检查／审查状态和阻断原因。

<a id="user-flow"></a>

## 用户操作示例

使用现有 DSH Web 会话／目录选择器与其作用域命令注册表。在受管理 profile 中增加一个仅供人使用的 `/project` 命令适配器；这是拟议功能，当前工作目录尚不可用。其内部复用原生 Goal 服务，但该 profile 不挂载原始 `/goal` 修改命令，避免绕过项目接收。常规 DSH profile 保留自己的命令。

| 用户操作 | 入口与必需结果 |
| --- | --- |
| 打开项目 | 现有目录／会话选择打开接收关闭的控制器；任何修改前展示规范化根目录与角色 profile，不需要 Shadow。 |
| 批准范围与检查 | 拟新增 `/project configure <JSON>` 预览 `allowedPaths`、`checks`（`id`、`command`）、`snapshotExcludes` 与生效限制；`/project confirm <previewId>` 批准准确的当前预览。 |
| 开始任务 A | 拟新增 `/project start <objective>` 使用批准配置创建并关联一个原生 Goal，然后开放接收。重复启动不能替换未完成 Goal。 |
| 停止或恢复 | 拟新增 `/project stop` 关闭接收并等待停稳；`/project resume` 验证身份、保留预算、源码与进程清理后，才恢复同一个 Goal。 |
| 修改检查或处理关注项 | 先停止，再提交新的 configure／confirm，使受影响证据失效，但不重置本 Goal 预算。身份／进程不确定时阻止恢复；`/project result` 展示未解决工作。 |
| 查看结果并继续 | 拟新增 `/project result` 展示当前差异、工作身份、真实检查输出、审查问题与下一项允许操作；A 验收后，后续明确启动才创建任务 B。 |
| 放弃未完成工作 | 拟新增 `/project abandon` 要求完全停稳，记录人工决定并清除原生 Goal，不删除历史、不宣称完成。开始其他任务仍是单独操作。 |

configure 解析器只接受已定义字段，对省略的排除项／限制使用确定性默认值，并展示解析后的值供确认。陈旧预览被拒绝。生成的检查建议在确认前不是可信命令。应用配置要求完全停稳；模型工具调用或看起来像斜杠命令的文本不能充当人工确认。

原生 `Goal.create()` 会立即启用续跑。启动处理器必须先关闭接收，创建 Goal 后同步停用，将批准的工作关联与预算持久化后才允许输入，再依据同一次人工启动授权明确恢复它。设置中断时保持关闭等待核对。`AT1-10` 验证包含修改检查与恢复的完整用户流程；不假设已有模态表单，也不新建桌面应用。

## 开发备注

按照[交付表](testAndAcceptance.zh.md#delivery)选择接入试验、受控试用或后续版本的必需用例，并验证功能的真实工具路径。原生 Team 回归测试是前提，不是新增权限或完成策略已经存在的证明。

2026-09-02，一次可丢弃的无密钥真实组合探针成功覆盖了子会话工具限制恢复、作用域内 Team 拒绝和 Goal 关联启动顺序。结果记录在[时间线](timeline.zh.md)中；这只是聚焦试验的支持证据，不表示角色 profile 或 `/project` 流程已经实现。
