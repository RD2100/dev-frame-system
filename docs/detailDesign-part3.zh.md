# 详细设计第 3 部分：Obsidian 记忆

[English](detailDesign-part3.md) | 中文

## 概述

本文定义[总体设计](generalDesign.zh.md)中的可选长期知识。执行历史由 DSH 原生日志负责，Vault 只保存经过选择的事实、偏好、经验和未解决问题。首版使用有界 Markdown 文件与普通文件系统操作，不引入新数据库或 embedding 服务。记忆内容是不可信上下文，不能授予工具、权限或指令权威。

## 需求与命名空间

用户必须在任何追加操作之前明确选择 Vault 根目录并启用写入。只读模式也是有效配置。根据调用会话解析项目的原生工作区身份，不接受模型提供的目录或其他项目 ID 作为身份。

| 编号 | 必要行为 | 验收位置 |
| --- | --- | --- |
| `R3.1` | 从调用者项目与明确允许的用户记忆中召回有界内容。 | [AT3-01、AT3-02](testAndAcceptance.zh.md#part3) |
| `R3.2` | 创建笔记时不覆盖、不越界、不因重试重复，并保留被外部改动的文件。 | [AT3-03、AT3-04、AT3-09](testAndAcceptance.zh.md#part3) |
| `R3.3` | 保留来源，区分确认事实、推断和陈旧上下文。 | [AT3-05、AT3-06](testAndAcceptance.zh.md#part3) |
| `R3.4` | 可选记忆失败时保持普通开发可用，并如实报告写入失败。 | [AT3-07、AT3-08](testAndAcceptance.zh.md#part3) |

首版是 DevFrame 管理的仅追加笔记区，不是对可任意编辑的 Obsidian Vault 进行通用同步。使用专用子树，根据安全宿主 ID 生成文件名，不扫描或整理整个 Vault。人工编辑、移动与重命名按下文处理，不悄悄导入。

```text
<vault>/devframe-memory/
  user/<noteId>.md
  projects/<workspaceId>/<noteId>.md
```

启用追加后，项目控制器可以追加自己项目的笔记。开发者与审查者只能读取各自允许的命名空间。用户级偏好只根据笔记引用的明确人工确认写入；Shadow 和控制器都不能把自己的推断提升为已确认偏好。

<a id="tools"></a>

## 记忆工具与限制

拟议接口包含三个工具。`scope` 选择 `project` 或 `user`，不接受任意路径。返回的摘录包含笔记身份、来源、新鲜度和截断信息。

| 工具 | 输入 | 输出 |
| --- | --- | --- |
| `memory_search` | `scope`、有界查询、可选且不超过配置上限的结果数量。 | 匹配笔记 ID、短摘录、日期和 `truncated`；读取笔记内容前执行范围检查。 |
| `memory_read` | `scope`、宿主签发的 `noteId`。 | 有界笔记内容与来源元数据；拒绝未知 ID 和超出允许命名空间的链接。 |
| `memory_append` | `scope`、稳定源事件引用、笔记类型、有界正文、可选被替代笔记 ID。 | 返回 `created`、`already_exists` 或明确失败；角色、同意、来源和内容检查由宿主负责。 |

初始可配置限制为每篇笔记 8 KiB、单次返回总内容 16 KiB、10 条搜索结果，以及每次搜索最多 200 个候选文件。按 UTF-8 编码字节计数，并只在有效字符边界截断。达到候选数量限制时明确返回覆盖不完整，不得宣称任何地方都不存在匹配知识。

搜索先处理项目本地文件与明确允许的用户笔记，使用确定性的文件名／元数据筛选及有界文本匹配。不要求后台索引进程。只有在更大语料上测得检索问题后，才考虑增加索引或向量存储。

笔记携带宿主规范化的**实体标签**：模型提议笔记所关于的主题，宿主将其规范化（限长、单主题形态、秘密筛查），并让每条项目笔记自动锚定其工作区。`memory_search` 接受实体过滤参数，"关于 X 的一切"就是一次确定性查找；supersession 链条充当有效期窗口。这些标签是知识图谱的实体锚定——不需要图数据库、抽取管线或实体间关系边：笔记本身就是事实节点，更丰富的结构等待实测需求。

瞬时读取／追加失败使用[第 4 部分](detailDesign-part4.zh.md#limits)中的有界重试策略，保留相同操作身份与候选内容。权限错误、冲突和不完整笔记不自动重试。

<a id="storage"></a>

## 读取与追加行为

每篇笔记包含 schema 版本、笔记 ID、命名空间、类型（`fact`、`preference`、`lesson` 或 `question`）、创建时间、源会话／事件引用、可选来源快照，以及陈述状态（`confirmed`、`observed` 或 `inferred`）。内容摘要标识实际存储的正文。身份和来源字段由宿主推导；模型提供的是候选文字，不是权威元数据。

1. 解析已配置的 Vault 和命名空间；拒绝目录穿越、非预期 symlink／reparse 组件，以及解析后越出允许根目录的路径。
2. 校验角色与追加授权、源事件归属、受支持 schema、笔记大小和内容筛查。
3. 根据命名空间与源事件派生稳定笔记 ID；重试保留候选正文，不重新生成。创建前先查询已提交回执：如有回执，校验其中记录的路径与摘要，返回 `already_exists`、`memory_changed` 或 `memory_missing`，不重新创建文件。
4. 使用受支持文件系统提供方的只创建操作独占创建文件，不截断或替换已有笔记。
5. 文件刷盘并关闭后，将其预期相对路径与完整文件摘要持久化到 DSH 会话日志，再返回 `created`。在回执之前崩溃时，文件内容尚未确认，不能当作已确认记忆。

最小实现可以使用独占创建（`wx`）与完整性摘要。读取方还要将完整文件与已提交的会话回执比较，不能通过编辑笔记自身元数据来替代回执。没有回执时，完整且匹配的候选内容可以由原追加操作重试确认；部分内容仍为 `incomplete_note`，保留等待明确修复。

| 外部变化 | 首版行为 |
| --- | --- |
| 用户编辑生成的正文或元数据 | 报告 `memory_changed`，保留文件，并从自动确认召回中排除。摘要不匹配只能证明发生变化，不能判断是纠正还是损坏。 |
| 用户移动、重命名或删除文件 | 在记录路径报告 `memory_missing`；不跨命名空间追踪文件、不自动重建，也不宣称已经同步。 |
| 用户在对话中明确提交修正 | 取得所需确认后，追加一篇有来源、替代旧笔记的新笔记；不覆盖被编辑的文件。 |

移动／改名监听、自动导入外部编辑和双向同步不在范围内。已经确认的文件消失后，不能仅因原追加操作重试就重新创建它。`AT3-09` 在临时文件上验证这些用户操作。

目标已存在且完整内容匹配时返回 `already_exists`；内容不同时返回 `memory_conflict`，不修改任一版本。同一源事件的并发追加最多产生一篇完整笔记。宿主互斥有帮助，但不能代替文件系统独占创建。

在实际部署文件系统上验证只创建和路径包含行为，包括受支持的 Windows 路径。如果适配器不能提供所需操作，就关闭追加并提供只读记忆，不退回无限制 shell 写入。这些检查约束 agent（智能体）选择的路径，不承诺抵抗另一个高权限本地进程恶意并发修改文件系统。

<a id="trust"></a>

## 信任、冲突与新鲜度

记忆是上下文，不是指令。在向模型注入之前标注笔记来源与信任状态，并将注入记录到会话事件日志，使其能够重建。笔记中要求忽略权限、执行命令或改变项目范围的内容，仍是被引用的数据，不能改变运行策略。

已确认用户偏好要求直接人工来源。项目观察保留其快照／版本适用范围。推断出的经验持续标为推断；模型给出的数字置信度不是证明。引用快照与当前项目不同时，将观察标为可能陈旧，并在据此行动前验证。

存在冲突的笔记一并展示，除非获授权的新笔记明确替代旧笔记。替代通过仅追加方式实现，且限定在同一命名空间，不删除旧来源。不能仅因为模型写得更晚，就把某条内容选为正确事实。

不向 Vault 复制完整会话、秘密、凭据、原始环境转储或不必要的个人数据。优先保存附带本地来源引用的简短获准结论。内容筛查能减少意外泄漏，但不是保证；可疑内容被拒绝时，不把疑似秘密回显到日志中。

<a id="failure"></a>

## 失败处理与集成

启用记忆时，在项目任务开始阶段召回一次，只在确有需要时追加明确读取。验收后复用控制器最终任务摘要作为项目笔记候选，不创建独立反思 agent 或另一轮自动模型对话。

| 失败 | 必需行为 |
| --- | --- |
| Vault 不可用或未配置 | 返回 `memory_unavailable` 与有界说明；普通开发可以不依赖召回继续。 |
| Vault 只读或追加未启用 | 在原生任务输出中保留候选摘要；不宣称已经保存到 Obsidian。 |
| 笔记过大、格式错误、不安全或包含秘密 | 给出具体原因并拒绝或排除；不使用放宽限制的兜底。 |
| 重试耗尽或笔记冲突 | 保留可见警告与稳定候选引用，要求明确修复决定。 |

记忆失败不撤销有效的代码验收。反过来，如果用户的主要任务就是保存或检索记忆，那么该失败就是任务失败；不能借可选可用性把未成功的记忆请求改称成功。
