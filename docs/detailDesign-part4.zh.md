# 详细设计第 4 部分：可靠性与日常运行

[English](detailDesign-part4.md) | 中文

## 概述

本文负责从首轮单项目验证起就使用的可靠性机制，不是推迟到记忆之后的最后阶段。DSH 提供会话、目标、工具、后台任务和持久化；DevFrame 必须实现接收、所有权与恢复接入。设计区分取消已请求与执行已停止，面向受支持的 Windows 路径，不承诺分布式高可用或恶意代码隔离。

<a id="recovery"></a>

## 恢复与续跑

恢复从读取状态开始，不从发送模型请求开始。在接受新的修改之前，校验固定的 DSH 版本、功能策略配置、工作区身份、控制器关联和角色描述记录。身份缺失或不一致时，返回可见的 `needs_attention`。

原生目标持久化与自动续跑是两回事。原生驱动器不会自动启用恢复或 fork 后的目标；保留这一行为。人工恢复操作要指明项目／运行与批准的限制，不会扩大权限，也不会清除已有用量。

在恢复会话能够运行之前安装 `agent/pre-step` 接收检查，覆盖控制器、子会话、排队跟进、投递重试和回调。拒绝已关闭或不匹配的工作关联，允许的工作调用 `next()`，并保留下游拒绝。`tools.guard()` 保护工具执行，但不能单独阻止模型请求；仅停用根 Goal 也不能阻止独立子会话。

原生前置步骤被拒绝会结束该轮，不会自动把已取出的消息放回收件箱。接收关闭时应避免唤醒工作。如果竞争或恢复触发拒绝，返回拒绝前在会话状态中保留原 goal／task／operation 及输入引用。只有明确证明没有任何模型或工具步骤执行过的已取出输入，才能标记为 `not_started`，并在获授权恢复后明确重发。如果已有任一模型或工具步骤执行，必须保留已执行事实，按中断工作核对；如果无法确定是否执行，则保持 `ambiguous`。中断或不确定工作都不能降级为 `not_started` 后重放。`AT4-01` 同时验证没有未授权执行和没有丢失已接受工作。

| 恢复时的条件 | 处理 |
| --- | --- |
| 关联已预留，目标会话不存在 | 获授权后用同一个预留 ID 核对或完成创建，不悄悄分配替代身份。 |
| 目标接受了消息，发送方回执缺失 | 按消息 ID 恢复目标回执，不重复排入面向模型的输入。 |
| 执行可能已开始，但没有终结结果 | 检查所属后台任务／进程证据和源码状态；无法确定结果时标为 `ambiguous`。 |
| 上次测试／审查后源码变化 | 使受影响证据失效，用户恢复后重新运行必需检查。 |
| 角色、策略或必需事件解码器不可用 | 保持只读，或给出诊断并拒绝恢复；不退回无限制默认值。 |

shell 命令、网络调用或面向用户的外部副作用不具备笼统的恰好一次保证。幂等投递防止重复输入；结果不确定的不可逆操作需要检查与人工决定。首期工作流本身不授权自动发布或部署。

<a id="stopping"></a>

## 停止与写入所有权

停止操作只针对所选项目及其已知后代，不针对 DSH 进程中的所有后台任务。使用原生子进程所有权与进程树句柄，不按可执行文件名或未经验证、可能复用的 PID 杀进程。

1. 关闭新工作接收、停用续跑，并记录停止请求。
2. 中止活动模型／工具操作，取消项目所属后台任务与子进程树。
3. 在配置的宽限期内等待工具回调、流、后台任务和子进程完成清理。
4. 持久化最终观察状态；只有确认完全停稳后才释放写入所有权。

超时时返回 `needs_attention` 和剩余所属工作，并继续禁止给项目分配新写入者。重启后的新进程必须先核对旧执行，再授予写入所有权；内存互斥丢失不代表旧子进程已停止。如果无法安全确认进程身份，要求人工处理。

插件 dispose（资源释放）遵循相同所有权规则：移除监听、仅取消自身定时器与工作、等待回调结束，不遗留活动写入者。测试既使用确定性替身，也使用真实受控子进程；任何测试都不得针对无关用户进程。

<a id="limits"></a>

## 限制与预算

以下是拟议初始 profile 参数，不是测得的容量，也不是当前 DSH 默认值。随部署变化的值应实现为经过校验的 Cordis 插件配置。测试使用更小的参数覆盖耗尽路径，避免高成本运行；记忆专用限制仍由[第 3 部分](detailDesign-part3.zh.md#tools)定义。

| 控制项 | 拟议初始值 | 含义 |
| --- | --- | --- |
| 同时活动项目数 | 2 | 第三个项目在有容量前保持未启动。 |
| 每个物理项目根目录的写入者 | 1 | 覆盖所有修改工具及其尚未结束的后台任务。 |
| 宿主全局并发模型请求 | 3 | 包含 Shadow、控制器、开发者和审查者。 |
| Team 生命周期成员上限 | 8 | 使用原生 `maxMembers`；包含失败记录，不随每个任务重置。 |
| 每个任务修复次数 | 2 | 首次审查后，最多进行两次修改／重测／复审循环。 |
| 每次项目运行的模型尝试数 | 80 | 控制器与后代合计，包含重试尝试。 |
| Shadow 每个用户轮次的模型尝试数 | 20 | 防止协调循环产生无限请求。 |
| 项目运行墙钟时间限制 | 30 分钟 | 耗尽后关闭接收并开始取消。 |
| 待处理消息数／消息大小 | 每目标 32 条／UTF-8 16 KiB | 入队前拒绝超限内容；较大产物使用引用。 |
| 瞬时投递／记忆尝试次数 | 总计 3 次，间隔依次为 1 秒和 3 秒 | 持久化计数，重启不重置。 |
| 停止宽限期 | 5 秒 | 到期后要求人工关注，不代表进程已经终止。 |

项目运行使用[第 1 部分工作身份](detailDesign-part1.zh.md#work-identity)，不另建 Run 数据库。控制器与子会话尝试通过原生会话事件计入派发时固定的 `(controllerSessionId, goalId)`。开放接收前恢复已使用和未结算预留；暂停／恢复、修改检查、重试和进程重启均不重置它们。迟到结果结算其原 Goal 的预留，不结算当前 Goal。

每次对外尝试前原子预留请求与并发容量；结束时释放并发，即使失败也保留已消耗尝试。提供方的隐藏重试必须先暴露或关闭，才能声称严格尝试次数限制。初始截止时间自首次启动持久化，包含暂停／停机经过的时间；用户可以明确调整限制，但不能抹去已有用量。只有单独获授权的新 Goal 才开始新预算。

能够取得真实 token 用量时予以记录，但区分测量用量、估算用量和未知用量。严格 token 或金额上限还要求提供方支持的上界，以及所有在途调用的预留；不确定预留在核对之前继续占用。没有这些支持时，只提供请求／时间限制和估算，不虚称严格金额限制。

原生 Goal Round 上限是独立循环保护，不是 token、金额或墙钟预算。权限拒绝、持久化失败和严重进程泄漏会停止运行，与剩余预算无关。自动重试不能通过创建新 Goal 来重置限制。

<a id="operations"></a>

## 可观测性与版本处理

使用现有 DSH 事件与产物。新记录只需要项目／工作区身份、会话／运行身份、角色、适用时的操作／消息 ID、源码快照、时间、结果和脱敏错误。不增加遥测数据库，不把完整提示词复制进诊断日志，也不把原始运行证据存进源码仓库。

UI 区分排队、已收到、执行中、等待审查、被阻断和已停止工作，并给出具体最近错误及下一项允许操作。重复且未变化的状态不产生新模型请求或重复通知。证据包含实际生效的提供方／模型配置；运行时无法证明身份时标为未经验证。

将 DSH 预发布版本与功能 profile 一起固定。在对已有运行数据使用新版本之前，按[验收参考](testAndAcceptance.zh.md#baseline)验证角色恢复、投递、取消和无密钥原生回归命令。本方案不承诺任意预发布版本之间的自动兼容。

回退功能部署时，先禁止新工作、等待所属执行停稳，并保留最后兼容的 profile 与事件读取器。DSH 可能拒绝未知的必需会话事件；只删除负责解码的插件并不是安全回退。不得为了让旧构建打开数据而删除或重写会话日志；应提供兼容读取／导出路径，或者保留数据不动并给出明确诊断。

任何新增公开会话事件类型都必须遵循 DSH 的类型化事件和消费方投影要求，配套作用域 effects 与相关快照。不能仅为了让回退看似成功，就把权限、完成或投递状态标为可忽略。

[交付表](testAndAcceptance.zh.md#delivery)选定提前验证的单项目停止／恢复与预算用例。更广的多项目与版本升级故障矩阵随相应后续候选功能验证；文件编号不表示把基础安全推迟到第四个里程碑。

## 开发备注

运行验收不是全量测试百分比，也不是一次正常流程演示成功。[AT4-*](testAndAcceptance.zh.md#part4)必须覆盖真实重启和进程行为，任何不受支持的环境都应明确保留为版本限制。
