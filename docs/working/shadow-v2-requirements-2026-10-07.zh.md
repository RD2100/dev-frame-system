# Shadow v2 需求 — 2026-10-07

[English](shadow-v2-requirements-2026-10-07.md) | 中文

## 概述

Shadow 为明确选定的项目提供稳定协调入口：恢复负责会话、查询已有任务板与记忆、引导人类作出代码审查判断、推进已授权工作，并反馈关联证据的结果。本文是需求参考和开发基线，不表示插件已实现或通过验收。

## 范围与授权 <a id="scope-and-authority"></a>

交付物是适配已安装 DSH 宿主的独立插件、可复现的隔离验证、可安装归档和维护说明，而不是新的通用开发平台。日用 profile 的安装或启用、发布均未获授权。

当前主会话担任开发组长。独立子 Agent 分析和审核需求、设计与代码，实施者不能批准自己的产物。技术开发审核不要求用户逐步批准；产品运行时必需的人类判断仍不得省略。

源码工作树是 [DSH 开发仓库](../../README.zh.md)，已安装宿主位于 `D:\DSH\DSH Desktop\resources\app`。两者依赖版本不同，兼容性声明必须列出实际验证的宿主和后端版本，不能从源码工作树推定兼容。

## 必要行为 <a id="required-behavior"></a>

| 编号 | 要求 | 可观察结果 |
|---|---|---|
| R1 | 持久保存项目与负责会话的关联。 | 重启恢复同一关联；优先复用已有负责会话，不重复创建。 |
| R2 | 明确处理多候选、离线或失效会话，以及重新绑定。 | 不任取首个候选；投递失败不静默替换负责人。 |
| R3 | 协调仅限选定项目与已授权操作。 | 列出或打开项目不代表授权执行任务，也不代表接管无关项目。 |
| R4 | 复用现有任务板作为任务、执行及验收的权威来源。 | 查询当前任务与执行记录，识别重复，关联真实任务和执行标识。 |
| R5 | 保证重试安全。 | 同一请求与内容不重复创建或启动工作；同一标识换用不同内容时拒绝。 |
| R6 | 读取相关用户偏好和项目决策，保存有来源的审查结论。 | 记录项目、请求、会话及证据，区分人类判断、模型建议与验证结果。 |
| R7 | 隔离项目记忆与代码访问。 | 当前选定项目范围之外的项目级记录与代码默认全部拒绝；全局用户偏好是明确、单独标明的例外。 |
| R8 | 产品运行时执行 rd-loop：概览、关键模块人类审查、总结。 | 展示概览与具体决策点；记录必要人类判断后才能推进依赖工作。 |
| R9 | 重试、重启和 Goal 续跑均保留等待人类状态。 | 等待不是失败；模型输出、插件转发和自动续跑均不能制造人类判断。 |
| R10 | 分别表示运输、审查、执行与验收结果。 | 消息送达不能说成审查完成、工作完成或验收通过；结果关联相应权威证据。 |
| R11 | 明确报告能力缺失或不兼容。 | 不可用后端返回可行动的能力或错误结果；受影响操作拒绝执行，独立只读工作仍可使用。 |
| R12 | 禁用或卸载不删除用户任务与记忆。 | 移除插件贡献，但保留现有后端任务、执行记录和记忆。 |

## 架构约束 <a id="architecture-constraints"></a>

轻核心依赖四个接口：`IProjectRouter` 负责项目身份、负责人和路由；`ITaskTracker` 适配现有任务与执行；`IMemory` 适配作用域记忆和来源；`ICodeReader` 使用宿主受控读搜。具体服务名、工具 schema、版本映射和传输细节仅放在适配器。

首批适配器面向已安装任务板后端与 engram，必须核对公开接口及实际挂载情况。不支持的后端组合应明确报不支持，不宣称兼容所有后端。

核心、入口、Shadow 自有绑定与请求持久化、当前适配器可放在一个插件，不强制拆成多个 npm 包。不得另造任务板、记忆数据库、Teams、Goal、会话或文件系统引擎；后端私有数据库不是集成 API。

模块各自承担当前明确职责，通过显式类型契约通信，不访问其他模块内部状态。持久化、取消、事件卸载与恢复均有明确负责人；部署可变控制使用校验后的配置，接口默认值在所属边界显式解析。

## 验收 <a id="acceptance"></a>

| 情形 | 必需的隔离证据 |
|---|---|
| A1：安装 | 经真实 DSH 启动器将归档安装到独立宿主 home/profile，加载插件并使用入口，不改变日用 profile。 |
| A2：完整结果 | 用户目标→项目与负责会话→任务与记忆查询→概览→真实人类模块判断→有来源总结或改进任务→授权执行→真实任务、执行和验收反馈。 |
| A3：隔离 | 两个项目具有不同负责人、代码和记忆；通过真实执行端证明允许访问，并拒绝读写其他项目的全部记录（含未特别标保护的记录）及跨项目代码访问。 |
| A4：重试 | 重复路由、创建任务、执行与人类判断投递；证明没有重复任务、执行或重复应用。 |
| A5：恢复 | 在持久化后及外部副作用前后中断，再重启；恢复绑定与等待人类状态，对账权威任务与执行。 |
| A6：人类边界 | 尝试模型工具、转发消息、错误项目输入、过期判断和 Goal 续跑批准；拒绝且不推进。当前真实人类判断仅接受一次。 |
| A7：缺失后端 | 分别缺省或禁用必要后端、拒绝不兼容版本；明确不可用操作，不报告成功。 |
| A8：禁用与卸载 | 移除插件贡献、等待生命周期静止，并验证后端任务与记忆仍存在且可独立读取。 |

源码单测、界面可见、收到消息、模型声称或跳过检查均不能替代真实宿主验收。证据记录产物版本或内容、宿主及后端版本、命令、结果和覆盖限制；输入改变会使依赖证据失效。

## 开发控制 <a id="development-controls"></a>

依次开展需求分析、概要设计、详细设计、实现和测试。每阶段由独立 Agent 审核并明确处置发现后再推进依赖工作。测试设计始于本需求，测试执行面向实际实现行为。

组长负责集成和共享构建输出。并发实施前明确子 Agent 写入范围与任务依赖，保留已有源码改动、日用配置及第三方数据。交接说明入口、支持的适配器、生命周期与恢复责任、可复现检查和剩余限制。
