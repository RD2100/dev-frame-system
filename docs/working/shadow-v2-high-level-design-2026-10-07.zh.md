# Shadow v2 概要设计

本设计定义适配已安装 DSH 运行时的独立 Shadow 插件，不是新的任务板、记忆库、Agent 引擎或通用开发流程平台。[需求基线](shadow-v2-requirements-2026-10-07.zh.md)负责产品范围与验收要求。

## 架构与职责

交付一个私有插件包，包含轻量应用核心、稳定的人类入口和可替换的 DSH 适配器。按职责划分模块，不要求每个接口独立 npm 包。宿主负责会话、模型执行、工具、权限、任务执行及后端数据；Shadow 负责项目—负责人绑定、请求状态、人类判断状态、副作用日志和证据引用。

依赖方向为入口 → 应用核心 → 四个契约 ← 适配器。核心不得导入 Cordis、DSH、任务板 SDK、Engram SDK、HTTP 路由或原生文件操作；只有组合根构建适配器并提供入口处理器。每个请求显式携带选定项目上下文，不设置可变的全局当前项目。

| 组件 | 职责 | 不承担的职责 |
| --- | --- | --- |
| 入口与组合根 | 人类界面、能力发现、配置校验、生命周期和适配器构建 | 业务状态转换和后端真实状态 |
| 应用核心 | 授权范围内的协调、请求转换、rd-loop 顺序和证据对账 | 模型循环、后端数据结构、文件系统执行 |
| IProjectRouter | 项目标识、负责人候选、绑定校验、路由回执和会话观察 | 任务验收或自动接管 |
| ITaskTracker | 项目范围内任务查询、授权创建／运行、执行和验收证据 | 根据移列或最后回复宣称验收 |
| IMemory | 按范围召回偏好／决策、带来源的记忆持久化 | 将模型建议当成人类判断 |
| ICodeReader | 授权根目录内有界、只读的代码发现和读取 | 编辑、终端访问、全盘搜索或读取凭据 |
| Shadow 持久状态 | 原子保存绑定、请求、判断、副作用意图和证据指针 | 复制任务板或记忆库的权威数据库 |

## 稳定入口与项目路由

入口先解析指定项目及持久负责人绑定，再路由。已有绑定必须重新核对项目身份、会话记录的工作目录、存在性和可用性；多个有效候选进入明确的选择状态。负责人离线、缺失、身份不符和已被替代分别表示；重新绑定是明确授权的操作，保留旧关联以便审计。

适配器在公共工作区／会话服务已挂载时使用它们；安装包存在不代表服务可用。只有当前请求授权时才创建新会话；挂载失败可能已经创建会话，必须按身份对账，不能盲目重试。保留后端按请求 ID 去重的语义。路由回执只代表投递受理，不代表审查完成、任务完成、反馈持久化或验收通过。

## 请求与 rd-loop 生命周期

请求区分 received、resolving、overview、waiting-human、module-review、summary、executing、observing、completed、failed、indeterminate。这些是协调状态，不替代宿主 Goal 或任务执行生命周期。协调请求完成后，仍分别报告任务执行和验收事实。

外部副作用前先持久保存请求身份、规范化输入摘要、选定项目、负责人绑定版本和已授权操作。相同身份及输入返回已有状态，不同输入产生冲突。只有所有权不重叠的独立请求才可并发；同一绑定或请求的变更串行化。

rd-loop 根据代码产出全局概览，然后在需要人类判断的决策前停止。有效人类判断选择下一模块或明确允许的总结路径；总结将真实判断、模型建议和验证结果分为不同来源。创建或运行改进任务必须具有覆盖对应项目和操作的已记录授权。

## 人类判断边界

当前宿主提供问题关联和普通连接认证，但没有发现公共、不可伪造的人类判断回执。source.kind=user、initiator 文本、Origin、普通 API cookie、模型回复、peer 消息或 Goal 续跑都不是人类授权证明；Shadow 不得仅凭这些值离开 waiting-human。

入口拥有私有人类判断验证能力，不新增第五个后端契约，也不向模型暴露批准工具。拟定首个安全提供者校验预先登记且获授权凭据产生的 WebAuthn 断言，强制用户在场和用户验证，由维护中的验证库处理协议。精确支持的 origin／RP 配置及凭据初始化属于详细设计要求；仅 IP 的 origin 或缺少可信登记时，不能悄悄降为较弱模式。

每个 challenge 绑定项目 ID、负责人／绑定版本、请求 ID、判断 ID、产物版本／摘要、允许动作及到期时间。验证与一次性消费原子提交后才能应用转换。过期、重放、绑定不符、模型生成和 relay 生成的输入不批准；缺少验证能力时保持可见的 waiting-human／capability-missing，任何自动轮次、超时或重启均不批准。

信任边界不包含已经控制宿主进程、操作系统、登记认证器或其可信登记流程的攻击者，但不假设模型没有普通终端或 HTTP 工具。最终运行时演练需要真实人类验证；虚拟认证器仅是协议测试证据，不是实际人类判断证据。

## 任务板适配与副作用恢复

首个适配器针对已安装 DSH 0.2.0-rc.2 上的任务板 0.4.5 公共能力。扩展面支持查询／创建／integration／事件，但没有 run；运行必须走已有完整工具执行管线，或使用宿主授权传输访问已记录的 HTTP action，不能用 setStatus、虚构服务、私有 ledger 或直接调用工具定义替代。

所有适配器操作在返回记录或发出副作用前落实选定工作区归属。权限确认仍归宿主负责，Shadow 不得伪造；协调授权不提高任务权限预设。

创建、运行、路由或记忆写入前持久记录副作用意图，对账后记录提供者请求身份及结果 task／execution／session ID。传输超时或崩溃可能留下 indeterminate：先查后端记录和保留的请求回执。有限后端去重／历史不等于永久恰好一次保证；不能证明副作用未发生或找到它时，保留 indeterminate，不自动重发。显式重试是新的授权操作，不是隐蔽重复。

观察 settlement 后读取完整公共执行／验收记录，按后端执行身份与游标去重。宿主 verification=passed 才是验收事实；succeeded、手动 done、关闭／跳过验收、界面回显和最终模型声明都不是。有限后端历史过期前保存必要证据，不建立竞争性的任务状态数据库。

## 记忆适配与来源

首个适配器使用 Engram 0.7.15 公共工具／HTTP。查询或写入前确定项目身份，不依赖进程工作目录；不虚构 ctx.engram 服务、新建记忆 HTTP 端点或任意后端来源字段。

Engram 按规范化 git origin 共享存储，包括工作树；共享 origin 不代表两个 Shadow 项目获准共享记录。不能证明后端范围等于选定项目时，适配器必须在公共执行边界将查询限制为明确标注项目归属的记录，或报告 project-scope-ambiguous；先取得其他项目记录再过滤不满足隔离。不默默导入归属不明的旧记录。

公共保存使用真实绑定的项目执行上下文；Shadow 自有来源记录将记忆 ID 关联到项目／请求／会话／任务／执行、产物版本及适用的人类判断回执。后端 sourceSessionId 不承载完整链；人类判断、模型建议和验证发现保持可区分。全局用户偏好是明确的范围例外，不授权读取其他项目决策。

## 代码读取适配

代码读取和搜索经过宿主公共文件系统／工具策略边界。在访问内容前，原生根目录规范化与符号链接／junction 处理必须拒绝越界；词法前缀或 cwd 均不够。适配器排除配置的敏感路径及凭据文件，限制结果数量／字节／时间并传播取消。首个提供者可明确仅支持本地原生工作区，不宣称支持所有文件系统。

宿主文件系统服务没有 glob／grep；已有搜索工具使用 subprocess，并包含隐藏／忽略文件。适配器必须在这一路径执行等效根目录与敏感路径约束，或通过受控文件系统服务提供有界遍历。不存在安全路径时报告 capability-missing，不得转为搜索整台机器。

## 持久化、重启与释放

使用带版本的 Shadow 自有 storage domain 保存原子状态快照；持久提交后才发布界面／事件。保存不透明后端身份、版本、游标、有界证据和授权关联，不复制第三方数据库。持久保存 waiting-human 与 indeterminate 副作用，使冷重启继续观察，而非重建任务或批准判断。

模型可见的协调消息及工具结果使用宿主标准会话事件和持久屏障；优先使用可重建的标准日志，而非卸载后打开旧会话所必需的私有 projection。发送受理与内存 stream 不是持久投递证据；验证包括 flush 和冷重开。

释放时移除入口 hooks／观察者，取消并收束自有操作，关闭自有存储；不删除宿主任务、会话或记忆。用户删除任务和遗忘记忆的入口仍独立可用。安装、停用、卸载和重启针对隔离状态验证，不改变日用 profile。

## 真实宿主兼容与验证

首个支持目标为已安装 Desktop 2.0.17 所使用的 DSH 0.2.0-rc.2 与 Cordis 4.0.4，而不是工作树的 0.1.6-alpha.1。bundle 元数据和 DSH peers 必须匹配真实运行时，兼容豁免不能代替测试。能力发现位于适配器，区分安装 artifact、已挂载能力及已执行结果。

主要真实组合环境通过已安装 dsh launcher 使用独立 custom web profile，显式隔离 home／状态／日志／任务 ledger／Engram dbDir／modelCacheDir，配置两个无关项目 fixture 和独立端口。prepareProfile 与 dump-config 可能写配置，都不指向日用 profile；仅 DSH_HOME 不隔离 Engram，也不隔离 Desktop 的 Electron userData／单实例锁。

custom-web 演练证明真实已安装运行时，不证明完整 Desktop 外壳。Desktop 验证需要可证明隔离的 userData／锁安排或独立 OS／VM，证据缺失时保留明确限制。无密钥验证不暗中触发付费模型调用、embedding 下载或发布。

## 阶段出口与维护交接

需求审核已完成；本文是待独立审核的概要设计草案，阻断发现关闭后才进入详细设计。详细设计必须先确定四契约类型、challenge／登记验证器、适配器执行上下文、对账规则、存储 schema、支持入口／origin 及 fixture 命令，再开始实现。

维护一份权威开发／证据记录，包含组长和组员身份、当前产物摘要、独立审核、实际命令／结果及剩余限制。最终交付包含可安装插件、适配器／权限文档、范围内源码与测试证据、冷重启及移除说明，并以 ZIP 区分正式交付物与内部审核记录。文件存在、源码测试或构建成功均不等于需求的最终验收。
